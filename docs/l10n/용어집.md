# 게임 용어집 — 폰즈 (FONS)

쓰는 사람이 매번 다른 표기를 만들지 않게, **표기 그 자체를 고정**하는 문서다.
뜻의 정본은 여기가 아니라 GDD다. 여기서는 "어떻게 쓰는가"만 정한다.

## 정본 순위

1. `data/*.json` 의 `name` · `name_ko` — 고유명사의 **철자 정본**
2. `docs/gdd/GDD_v8.0_00_확정사항.md` — 시스템 용어의 **뜻 정본**
3. 이 문서 — 문서·UI에서의 **표기 규칙**

셋이 어긋나면 1 → 2 순으로 이긴다. 이 문서가 이기지 않는다.

## 철칙

- 새 고유명사는 **데이터에 먼저 넣고**, 같은 이름을 여기 등록한 뒤에 쓴다.
- 한 번 등록된 표기는 문장이 어색해도 바꾸지 않는다. 바꿔야 하면 아래 "폐기 표기"에 남긴다.
- 같은 대상을 두 이름으로 부르지 않는다. 괄호 병기(주민(구 유민) 같은 표기)도 금지 — 구 이름은 이 문서에만 남긴다.

## 검사

```bash
./.venv/bin/python tools/check_glossary.py             # 표기가 정본에 있는가 (낱말 단위)
./.venv/bin/python tools/check_glossary.py --deprecated # 폐기 표기가 쓰는 문면에 남았는가
./.venv/bin/python tools/humanizer_scan.py              # 문서별 번역투 밀도 점수표
```

- 기본 검사는 낱말 경계로 본다. 골드러시 같은 합성어 하나 때문에 골드가 통과하지 않는다.
- `--deprecated`는 경고다. `수호`(defend 미션)처럼 폐기와 현행이 같은 철자인 말이 있어 기계가 자동으로 고치지 못한다. 확인하고 손으로 고친다. `--strict`를 붙일 때만 exit 1.
- `humanizer_scan.py`는 고치지 않고 잰다. 밀도 0순위부터 읽되, 표 안 화살표와 `구조적 적자` 같은 기술 용어는 후보에서 빼고 본다.
