# ADR 0008 — 세이브는 입력과 변한 것만 저장하고, 파생은 다시 만든다

## 맥락

이 저장소에는 아직 세이브가 없다. `godot/core/run_state.gd` 첫 주석이 "아직 없는 것: 소환·영지·저장"이라고 적고 있고,
[DEV_PLAN](../dev/DEV_PLAN.md) P5-1 이 `godot/autoload/save_manager.gd` 를 남은 일로 들고 있다. 그런데 지금 런은
이미 잃을 것이 많다 — 층 진행, 영웅 HP, 각인된 기술, 스킬 XP, 융합, 장비, 영지 저장분, 사육 마물.

원본 Unity 구현은 세이브를 이미 갖고 있었다. 규칙도 문서에 남아 있다.

- "단일 JSON 덤프 + 원자성(임시파일→교체) + 손상 시 `.corrupt.bak` · 세션 격리" (원본 대조 — `docs/gdd/AGENTS_원본.md` §5)
- "단일 JSON + 원자성(`.tmp`→`File.Replace`) + `.corrupt.bak` + 마이그레이션(`SaveMigration`)" (원본 대조 — GDD 03 P1-1)
- 스키마는 v6→v7(성격), v7→v8(AI 스냅샷), v12→v13(종점 키워드 1장)처럼 **필요할 때만** 올라갔다 (원본 대조 — 확정 #44·#47·#39)

그래서 형식은 새로 발명할 것이 아니다. 정할 것은 **무엇을 파일에 넣고 무엇을 다시 만드느냐** 하나다.

## 대안

1. **전체 스냅샷** — 영웅 딕셔너리를 스탯·전투 유닛까지 통째로 저장한다.
   구현은 짧지만, 스탯 밸런스를 고쳐도 구세이브는 옛 수치로 돈다. 파일도 커지고, 저장 구조가 코드 구조와 같이 바뀔 때마다 깨진다.
2. **입력만 저장** — 시드만 저장하고 전부 다시 만든다.
   가장 작지만, 각인·XP·연계·HP 처럼 **플레이가 만든 상태**가 사라진다. 다시 만든다는 말이 성립하지 않는다.
3. **입력 + 변한 것만 저장, 파생은 다시 만든다.**

## 결정

3번. 저장 파일은 두 층으로 나눈다.

| 층 | 예 | 저장? | 왜 |
|---|---|---|---|
| 입력 | 실행 시드 · 등급 · 레벨 · 시작 층 · 직업 배정 | 한다 | 같은 시드 = 같은 영웅이 이미 보장된다 (`heroes_from` 이 시드로 뽑는다) |
| 변한 것 | 층 · 영웅 HP/생존 · 각인·XP·연속·연계 · 장비 · 지갑 · 영지 저장분 · 사육 · 도감 | 한다 | 플레이가 만든 값이라 다시 만들 수 없다 |
| 파생 | 최종 스탯 · 전투 유닛 · 조우 편성 · 스냅샷 · 로그 · 적 목록 | **안 한다** | 정본 데이터와 시드에서 결정론적으로 다시 만든다 |

부수 결정 넷을 같이 못박는다.

1. **버전은 정수 하나(`schema`)로 시작해 1부터 센다.** 마이그레이션은 `1→2` 처럼 한 칸씩 이어 붙이고, 건너뛰지 않는다.
2. **필드 추가는 버전을 올리지 않는다.** 기본값으로 채울 수 있으면 마이그레이션이 아니다 (원본 GDD 04 B-10 "은행 필드 없는 구세이브 — 자동 초기화 · 마이그레이션 불요" 와 같은 판단).
   버전은 **이름이 바뀌거나 뜻이 달라질 때만** 올린다.
3. **더 새 버전은 읽지 않는다.** 모르는 필드를 버리면 조용한 데이터 손실이 된다. 파일을 그대로 두고 "이 세이브는 더 새 판" 이라고 알린다.
4. **파생 값을 파일에 넣지 않는다.** 넣는 순간 "정본은 무엇인가"가 둘이 되고, 밸런스 수정이 구세이브에 닿지 않는다.

## 결과

**얻은 것**
- 세이브 파일이 작다. 영웅 5인의 스탯·유닛을 빼면 수십 KB 수준으로 본다 (구현 전 추정 — P5-1 에서 잰다).
- 밸런스를 고치면 구세이브도 새 수치로 돈다. 저장된 것은 결정에 쓰인 값뿐이다.
- "무엇이 정본인가"가 한 줄로 남는다 — 저장 파일은 입력과 변한 것이고, 나머지는 `data/` 와 시드의 함수다.

**잃은 것**
- 불러오기가 **다시 만드는 절차**를 거쳐야 한다. 파생 재구성이 틀리면 세이브가 아니라 새 게임이 열린다.
  그래서 완료 정의에 "같은 세이브를 두 번 불러 같은 다음 층이 나온다"를 넣었다.
- 영웅 생성 경로가 바뀌면(예: `heroes_from` 인자 추가) 세이브가 그대로는 안 열린다. 이때는 필드 추가 규칙(버전 유지 + 기본값)으로 흡수한다.
- 전체 스냅샷보다 코드가 조금 길다. 대신 데이터 손실 위험이 낮다.

세부 형식·절차·테스트는 [세이브 불러오기 설계](../design/세이브_불러오기_설계.md) 가 정본이다.
