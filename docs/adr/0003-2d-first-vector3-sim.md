# ADR 0003 — 심은 `Vector3` 로 말하고 뷰가 축을 접는다

## 맥락

2D로 먼저 만들고 나중에 3D로 간다. 순진하게 만들면 심(규칙·상태)이 `Vector2` 로 좌표를 들고,
3D로 갈 때 심 전체를 고쳐야 한다. 그때 좌표를 쓰는 곳은 전투·이동·탑·영지 어디에나 있다.

## 대안

1. **지금은 2D로 만들고 3D에서 갈아엎는다.** 가장 빠르게 2D를 얻지만, 심과 뷰가 섞여 있으면 전환 비용이 심 크기에 비례한다.
2. **처음부터 3D.** 2D 화면을 3D 카메라 직교 투영으로 흉내 낸다. 전환은 공짜지만 2D 작업이 계속 어색해진다.
3. **심은 평면 좌표를 `Vector3` 로 들고(`y` 는 높이), 2D 뷰가 축을 접는다.**

## 결정

3번. 심은 `Vector3` 만 쓰고, 2D 뷰가 `FonsProjection` 으로 화면 좌표를 만든다.

- `game/view/view_contract.gd` — 뷰가 지켜야 할 계약 (`mount`/`apply`/`unmount`, `intent` 시그널)
- `game/view/view_factory.gd` — 모드 문자열(`2d`/`3d`)을 아는 **유일한 곳**
- `game/view/projection.gd` — `Vector3` → `Vector2` 순수 함수. 축 선택(`XZ` 탑다운 / `XY` 횡스크롤)만 다르다
- `game/main/main.gd` — 2D인지 3D인지 모른다. 뷰를 만들어 스냅샷을 밀어 넣을 뿐이다

3D를 붙일 때 하는 일은 `game/view/view_3d/view_3d.tscn` 을 만들고 `ProjectSettings` 의 `fons/view_mode` 를
`3d` 로 바꾸는 것뿐이다. 심과 조립 루트는 건드리지 않는다.

## 결과

**얻은 것**
- 전환 비용이 뷰 계층 하나로 격리된다. 심은 2D/3D를 모른다.
- 투영이 순수 함수라 단위 테스트가 쉽다 (축별 부호·스케일을 직접 검증한다).

**잃은 것**
- 2D 코드가 `Vector3` 를 쓰는 것이 처음엔 어색하다. `z` 를 안 쓰는 경우가 많다.
- 뷰 계약을 우회하는 코드가 하나라도 생기면 이 격리가 무너진다. 그래서 팩토리 밖에서 모드 문자열을 읽지 않는다.

**주의**
- 에셋은 경로가 아니라 **문자열 키**로 가리킨다 (`"hero:knight"`). 지금은 키→색으로만 해석하고,
  스프라이트가 생기면 매핑표만 갈아 끼운다. 파일 경로를 심에 넣으면 3D 전환 때 다시 고쳐야 한다.
