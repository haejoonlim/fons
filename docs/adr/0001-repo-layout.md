# ADR 0001 — 레포 구조: 엔진 프로젝트 격리와 기능별 배치

## 맥락

이 저장소는 엔진 프로젝트 하나가 아니다. 기획 문서, 원본 대조 자료, 밸런싱 정본 JSON,
파이썬 검증 게이트, 그리고 Godot 프로젝트가 같이 들어 있다. 이걸 한 덩어리로 두면
Godot이 문서· venv·도구까지 임포트 대상으로 훑고, 반대로 파이썬 게이트가 엔진 폴더를
알아야 한다.

Godot은 폴더 구조를 강제하지 않는다. 그래서 선택지가 실질적으로 세 가지였다.

## 대안

1. **레포 루트를 Godot 프로젝트로.** `project.godot` 이 최상위에 있고 `docs/`, `tools/`, `data/` 가 그 아래.
   가장 짧은 경로지만, Godot의 파일시스템 도크에 `.venv` 와 문서가 전부 뜨고
   `.gdignore` 를 여기저기 붙여야 한다.
2. **종류별 분리** — `scenes/`, `scripts/`, `assets/` 를 최상위에 두고 스크립트를 전부 `scripts/` 에 모은다.
   작은 프로젝트에선 읽기 쉽지만, 씬 하나를 고칠 때 씬·스크립트·전용 리소스를 서로 다른 폴더에서 오가야 한다.
3. **엔진 프로젝트를 `godot/` 로 격리 + 내부는 기능별 배치.**

## 결정

3번. 그리고 Godot 프로젝트 **안쪽**은 기능별로 나눈다.

```
godot/
  project.godot
  autoload/          전역 시스템 (GameState, DataLoader) — 씬 없음
  core/              순수 규칙 (gacha, combat) — 씬 없음, 단위 테스트 대상
  game/              씬과 그 씬 전용 스크립트·리소스 (근접 배치)
    main/            main.tscn + main.gd — 조립 루트
    view/            2D/3D 표시 계층 (계약·팩토리·투영 + view_2d/, view_3d/)
    ui/              title/ 같은 화면별 UI
  assets/            여러 씬이 공유하는 런타임 에셋
  data/              정본 JSON (res://data)
  tests/unit/        GUT 테스트
addons/gut/          벤더링된 테스트 프레임워크
```

엔진 **밖**은 목적별로 나눈다: `docs/`(문서), `tools/`(게이트·동기화), `sim/`(파이썬 규칙 검증),
`data/`(이관 원본 + manifest), `art-source/`·`audio-source/`(편집 원본), `build/`(산출물, 미추적).

## 결과

**얻은 것**
- Godot이 문서·venv·도구를 임포트하지 않는다. `.gdignore` 를 쓸 일이 없다.
- 씬 하나를 고칠 때 한 폴더 안에서 끝난다 (`game/view/view_2d/` 안에 씬과 스크립트가 같이 있다).
- 규칙(`core/`)과 표현(`game/`)의 경계가 폴더로 드러난다. 규칙은 씬 없이 테스트할 수 있다.

**잃은 것**
- 경로가 길어졌다. `res://scripts/...` → `res://game/...`. 문서·설정·씬 참조를 한 번에 고쳐야 했다.
  이동 뒤 GUT 전건 통과와 헤드리스 실행으로 확인했다.
- 폴더가 다섯 개 늘었다. 파일이 적을 때는 빈 방처럼 보인다.
  그래서 **에셋·화면 폴더는 실제 파일이 생길 때 만든다.** 지금 `assets/` 에는 규칙 문서만 있다.
