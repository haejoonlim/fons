# ADR 0010 — 칙령 2슬롯은 30층 설계로만 두고 구현은 보류한다

> 후속: [ADR 0011](0011-decree-second-slot-rules.md) — 교체 규칙·화면 조작·쿨다운을 정했고, 2026-10-25 에 구현까지 끝냈다. 이 ADR 의 "보류" 결정은 그것으로 대체됐다.

## 맥락

GDD 04 §3.7 은 "기본 1슬롯 · **30층부터 2슬롯** (동시 발효 2개 — §3.10) · 변경 쿨다운 5층 (가안)" 이라고 적는다. §3.10 은 30층 해금 목록에 "칙령 2슬롯 — 동시 발효 2개" 를 넣고, 조합 긴장(중상주의+채집장려 = 민심 -20)까지 예시한다.

현행 구현은 1슬롯이다. `data/estate.json` 의 `decrees` 에는 목록과 해금 층만 있고, 코어는 켜진 칙령 하나, 화면은 그 하나, 세이브는 문자열 하나를 쓴다. 2026-10-25 에 죽은 `edicts` 블록을 지우면서 그 안에 있던 `slot_count_by_floor`·`change_cooldown_floors` 도 함께 사라졌다. 이 ADR 은 그 둘을 다시 넣을지, 넣는다면 지금 구현할지를 정한다.

## 대안

1. **지금 구현** — 데이터에 슬롯 표·쿨다운을 넣고, 코어·화면·세이브를 배열로 바꾼다.
2. **데이터만 복원** — `decrees` 에 `slot_count_by_floor`·`change_cooldown_floors` 를 넣고 코드는 1슬롯으로 둔다.
3. **보류** — 30층 설계는 GDD 에만 두고, 구현은 선행 조건이 갖춰질 때 한다.

## 결정

**3번.** 지금은 1슬롯을 유지하고 데이터에도 슬롯 표를 넣지 않는다.

이유는 셋이다.

- **30층까지 가려면 10층 해금이 먼저 열려야 했다.** 영지가 들고 있는 층 값은 새 게임의 1층에 머물고 필드 층을 따라가지 않았다. 층을 깨도 갱신되지 않고 세이브에도 없었다. 그래서 실제 플레이에서는 10층 해금 판정이 계속 1층으로 돌았고, 테스트만 층 값을 직접 세팅했다. 2026-10-25 에 이 연결을 고쳤다 — 영지 층을 런 층의 파생으로 두고 층 클리어·불러오기·재시작에서 맞춘다. 이제 30층 자체는 닿는다.
- **교체 규칙이 정본에 없다.** 슬롯이 둘일 때 세 번째 칙령을 고르면 어느 칸을 밀어낼지, 같은 칙령을 두 칸에 둘 수 있는지, 파업 조기 종료와 어떻게 맞물리는지가 GDD 에 없다. 지금 구현하면 이 셋을 코드가 발명한다.
- **쿨다운은 가안이다.** "변경 쿨다운 5층 (가안)" 은 확정 수치가 아니다. 등록소(`tools/tracked_numbers.json`)에 올리지 않은 값을 코드에 넣으면 수치 정본 규칙(AGENTS.md §4)과 충돌한다.

2번(데이터만 복원)도 고르지 않았다. 읽는 코드가 없는 설정은 방금 지운 `edicts` 블록과 같은 죽은 데이터가 된다. 30층 설계는 GDD 04 §3.7·§3.10 이 이미 들고 있으므로 데이터에 사본을 둘 이유가 없다.

## 결과

**얻은 것**

- 지금 동작(1슬롯)과 데이터가 일치한다. 죽은 설정이 다시 생기지 않는다.
- 2슬롯을 붙일 때 정해야 할 것이 문서로 남는다.

**잃은 것 / 선행 조건**

- 30층 2슬롯은 아직 게임에 없다. 30층 이후 칙령 조합 긴장(§3.7)도 검증할 수 없다.
- 구현 전에 다음을 먼저 정한다.
  1. ~~영지 층 값을 필드 층에 동기화한다~~ — 2026-10-25 완료. 영지 층은 런 층에서 파생하고, 층 클리어·불러오기·재시작에서 맞춘다. 세이브에는 런 층만 있다.
  2. 두 슬롯의 교체 규칙과 화면 조작(어느 칸을 밀어내는가)을 GDD 또는 후속 ADR 로 확정한다.
  3. 쿨다운 5층을 확정 수치로 올리고 `tools/tracked_numbers.json` 에 등록한다. 확정 전에는 쿨다운 없이 슬롯만 늘리는 안을 먼저 검토한다.
  4. 켜진 칙령 하나를 문자열로 저장하는 형식을 배열로 바꾸는 `schema` 마이그레이션을 정한다.
- 이 결정을 뒤집을 때는 새 ADR 을 쓴다.
