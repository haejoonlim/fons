# ADR — 결정 기록

구조·기술 선택을 **왜** 그렇게 했는지 남긴다. 코드는 "무엇"을 말하지만 "왜"는 말하지 않는다.

## 형식

각 문서는 네 칸이다. 짧아야 한다 — 길어지면 아무도 안 읽는다.

```
# ADR NNNN — 제목
## 맥락     어떤 상황에서 결정해야 했나
## 대안     무엇을 비교했나
## 결정     무엇을 골랐나
## 결과     무엇을 얻고 무엇을 잃었나 (되돌리는 비용 포함)
```

## 규칙

- **뒤집지 않는다.** 결정이 바뀌면 기존 ADR 을 고치지 말고 새 번호를 쓴다.
  기존 문서 상태를 `대체됨: ADR NNNN` 한 줄로 표시한다.
- 파일명은 `NNNN-kebab-case.md`. 번호는 다시 쓰지 않는다.
- 구현 세부(함수명·라인 번호)는 적지 않는다. 그건 코드가 바뀌면 거짓이 된다.
