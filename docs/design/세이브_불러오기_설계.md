# 세이브 · 불러오기 설계

결정은 [ADR 0008](../adr/0008-save-schema.md) 이다 — **입력과 변한 것만 저장하고, 파생은 다시 만든다.**
이 문서는 그 결정을 파일 형식·절차·테스트로 내린다.

작성 2026-10-24 · 근거는 이 저장소 코드(`godot/core/`)와 원본 대조 기록(`docs/gdd/AGENTS_원본.md` §5 · GDD 03 P1-1).

**구현 상태 (2026-10-24)** — 코드·화면·테스트가 다 들어갔다.
`godot/core/island_clock.gd` · `godot/core/save.gd` · `godot/autoload/save_manager.gd` ·
각 상태 클래스의 `to_save()`/`from_save()` · 타이틀(`game/ui/title/`) · 필드 자동 저장 ·
영지 일과(`FonsDay.run`)와 메인 루프의 섬일 정산 호출 · GUT 391건 전건 통과 (2026-10-24).
정산은 시계와 함께 **생산·세금·식량 소비·인구증가·유지비**를 돈다 — 수치는 `estate.json` 에서 읽는다 (§4-3).
민심·아사·파업까지 붙었다 — 농사·시설 건설은 아직이다 (04 §3.4·§3.5·§3.14).
새로 시작은 확인창을 거쳐 세이브를 지운다 — 백업까지 지워 옛 런이 되살아나지 않는다 (§6).

## 1. 무엇을 저장하나

### 저장하는 것 — 입력

| 값 | 지금 어디 있나 | 왜 입력인가 |
|---|---|---|
| 실행 시드 | `FonsRunState._seed` | 같은 시드 = 같은 영웅 (`heroes_from` 이 시드로 뽑는다) |
| 등급 · 레벨 | `heroes_from(grade=5, level=130)` 인자 | 지금은 고정값이지만 소환·성장이 붙으면 값이 된다 |
| 시작 층 · 현재 층 | `_start_floor` · `floor` | 런의 위치 |
| 직업 배정 | `keyword_jobs(job_tree, party_size)` 결과 (`job_id`) | 시드에서 나오지만, 트리가 바뀌어도 저장된 사람은 그대로여야 한다 |
| 정본 판 | `data/manifest.json` 의 파일 목록 | 어느 데이터로 만든 세이브인지 확인용 (읽기를 막지는 않는다) |

### 저장하는 것 — 변한 것

| 값 | 지금 어디 있나 | 비고 |
|---|---|---|
| 영웅 HP · 생존 | `heroes[i]["hp"]` · `["alive"]` | 층을 넘어 이어진다 |
| 성격 | `brain.identity` = `{main, subs, seed}` | 롤을 다시 돌리면 다른 사람이 된다 — 반환값을 그대로 저장한다 |
| 행동 카운터 | `brain.counters` | 태그 → 횟수 |
| 최근 태그 · 최근 기술 | `brain.recent` · `recent_skills` | 융합의 "요즘 번갈아 쓰는가" |
| 스킬북 | `brain.book[id]` 의 `stage`·`level`·`xp`·`heat` | 나머지 필드(이름·태그·효과)는 카탈로그에서 다시 채운다 |
| 연계 | `brain.links` · `brain.link_sessions` | "A\|B" → 횟수 · 서로 다른 판에서 함께 쓴 횟수 |
| 각인 · 융합 목록 | `brain.born` · `brain.fusions` | 로그·표시용 |
| 판단 흔적 | `brain.last_tag` · `last_skill` · `streak` · `decisions` | 다음 판단의 출발점 |
| 지갑 | `GameState.gold` · `pull_count` | 소환이 붙으면 마석·티켓을 더한다 |
| 영지 저장분 | `FonsEstate.stores` · `population` · `morale` · `shortage_days` · `strike_floors_left` · `unrest_floors` · `recovering` | 아이템 → 수량 · 주민 수(자연증가가 비율이라 소수로 든다) · 민심·연속 부족일 · 파업 잔여 층·민심 미달 연속 층·회복 중 여부 |
| 섬일 | `estate` 시계 — §4 | `clock_epoch`·`last_settled_day` 만 쓰고 날짜는 시계에서 파생한다. `FonsDay` 는 층 안의 하루라 저장하지 않는다 |
| 사육 마물 | (런타임 없음 · `data/monster_husbandry.json`) | 획득 경로가 생길 때 `owned` 배열로 넣는다 |
| 도감 발견 | (런타임 없음 · `data/ecology_codex.json`) | 같은 방식으로 `discovered` 배열 |

### 저장하지 않는 것 — 파생

최종 스탯, 전투 유닛, 조우 편성, 적 목록, 로그, 화면 스냅샷, 조우 지점 배치(시드로 재현), 필드 좌표(층 시작으로 돌아간다).

이 값들은 `data/` 와 시드의 함수다. 저장하면 밸런스 수정이 구세이브에 닿지 않고, 파일 안에 정본이 둘이 된다.

## 2. 파일 형식 (`schema` 1)

경로는 `user://saves/slot_1.json` — 슬롯마다 파일 하나, 세션(실행)과 분리한다. 원본 규칙 그대로 단일 JSON 덤프다 (원본 대조).

```json
{
  "schema": 1,
  "saved_at": "2026-10-24T21:40:00",
  "data_manifest": "2026-10-17",
  "run": {
    "seed": "265",
    "grade": 5,
    "level": 130,
    "start_floor": 1,
    "floor": 48
  },
  "wallet": { "gold": 0, "pull_count": 0 },
  "estate": { "clock_epoch": 1793000000, "last_settled_day": 12, "stores": { "herb": 4, "wood": 9 } },
  "husbandry": { "owned": [] },
  "codex": { "discovered": [] },
  "heroes": [
    {
      "index": 0,
      "job_id": "l2_vanguard",
      "hp": 18422,
      "alive": true,
      "equipment": [],
      "identity": { "main": "난폭", "subs": ["호기심", "세심"], "seed": 918273 },
      "counters": { "근접타격": 41, "정찰": 18 },
      "recent": ["근접타격", "정찰"],
      "recent_skills": [7],
      "book": [
        { "id": 7, "stage": 2, "level": 4, "xp": 17, "heat": 3.2 }
      ],
      "links": { "7|31": 6 },
      "link_sessions": { "7|31": 3 },
      "born": ["빙결강타"],
      "fusions": [],
      "last_tag": "근접타격",
      "last_skill": 7,
      "streak": 2,
      "decisions": { "근접타격": 41 }
    }
  ]
}
```

- 숫자는 **문자열로 쓰는 자리가 있다.** Godot 4.7.2 의 `JSON.parse_string` 은 정수도 float 로 돌려준다 (실측 — `{"seed": 7}` → `TYPE_FLOAT`).
  그래서 64비트 시드(`run.seed`)는 문자열로 쓰고 읽을 때 `int()` 로 바꾸며, 나머지 정수(`schema`·`hp`·`id`·`stage` 등)도 읽을 때 `int()` 를 거친다.
  float 정밀도(2^53)를 넘길 수 있는 값은 시드뿐이다.
- `identity` 는 `FonsPersonality.roll` 이 돌려주는 `{main, subs, seed}` 그대로다 — 소환 규칙을 다시 돌리지 않는다 (근거는 `godot/core/personality.gd` 주석).
- `book` 항목의 `id` 는 `data/skills_catalog.json` 의 id(정수)다. 없는 id 는 불러올 때 **버린다**(카탈로그가 줄었을 수 있다).
- `equipment` 는 지금 `[]` — 3등급 한 벌이 등급에서 파생되기 때문이다. 획득·강화가 붙으면 아이템 id 배열로 바꾸고 `schema` 를 올린다.
- 모르는 최상위 키는 **읽을 때 무시하되 파일은 고치지 않는다**. 저장할 때만 지워진다.

## 3. 쓰기 · 읽기 절차

### 쓰기 (원자성)

1. `user://saves/slot_1.json.tmp` 에 전부 쓴다. `flush()` 후 닫는다.
2. 기존 파일이 있으면 `slot_1.json.bak` 으로 **한 세대만** 옮긴다.
3. `DirAccess.rename_absolute(tmp, target)` 로 교체한다.
4. 교체가 실패하면 tmp 를 남기고 오류를 반환한다 — 반쯤 쓴 파일이 정본이 되면 안 된다.

원본은 `File.Replace` + `.corrupt.bak` 를 썼다 (원본 대조). Godot 에는 `File.Replace` 가 없으므로 위 3단계가 같은 역할을 한다.

### 읽기

1. 파일이 없으면 "새 게임" 이다. 오류가 아니다.
2. `JSON.parse_string` 이 실패하거나 `schema` 가 숫자로 읽히지 않거나 1 미만이면 **손상**이다 —
   `slot_1.corrupt-YYYYMMDD-HHMMSS.json` 으로 옮기고, `.bak` 이 있으면 그것으로 한 번 더 시도한다. 둘 다 실패하면 새 게임을 제안한다.
3. `schema` 가 이 빌드가 아는 값보다 **크면** 읽지 않는다. 파일을 고치지 않고 "더 새 판" 이라고 알린다 (ADR 0008).
4. 마이그레이션은 `schema` 1 → … → 현재까지 **한 칸씩** 적용한다.
5. 파생을 다시 만든다 — `heroes_from(...)` 로 유닛을 만들고, 저장된 `hp`·`alive`·`job_id` 를 덮어쓴다.
   `identity` 는 저장값을 쓰고, 스킬북은 카탈로그로 채운 뒤 `stage`·`level`·`xp`·`heat` 만 저장값으로 바꾼다.

### 코드 경계

| 파일 | 역할 | 규칙 |
|---|---|---|
| `godot/core/save.gd` (`FonsSave`) | 형식·버전·마이그레이션 | 씬·노드·파일 접근 없음. 사전만 받고 사전만 낸다 |
| `godot/core/island_clock.gd` (`FonsIslandClock`) | 섬일 날짜·정산 판정·계절 | 파일도 시계도 모른다 — `now` 를 인자로 받는다 |
| `godot/autoload/save_manager.gd` | 파일 IO·원자성·백업·손상 격리 | 경로와 시각만 안다. 규칙은 `FonsSave` 에 둔다 |
| `godot/core/run_state.gd` 등 | `to_save()` · `from_save()` 로 자기 몫만 낸다/받는다 | 남의 상태를 만지지 않는다 |

`FonsSave` 가 씬을 모르는 이유는 테스트 때문이다 — GUT 이 파일 없이 사전 왕복만 검사할 수 있어야 한다 (ADR 0001 의 `core/` 경계).

## 4. 하루 경계 — 섬일 (확정 2026-10-24)

**시간 기준이다. 층 개수 기준이 아니다.** GDD 04 §3.13 이 2026-09-17 에 이미 정했다 — "주민 세금·식량 소비·인구 자연증가·채집 쿨·농사 성장·유지비는 전부 **섬 하루** 기준 (`estate.json *_per_island_day`·`*_island_*`) — 층 클리어 횟수와 독립". 층 단위로 남는 것은 민심·사기/아사 민심 패널티·파업 기간뿐이다.
같은 문서가 "런 기간(섬일)이 영지 경제의 유일한 시간 변수"라고 한 줄 더 적었다 (§3.2). 그래서 "층 5개 = 하루" 안은 버린다. 정본에 있는 단위를 그대로 쓰고 새 수치를 만들지 않는다.

### 4-1. 시계

| 값 | 정의 | 파일에 쓰나 |
|---|---|---|
| 배속 | 섬 1일 = 현실 `86400/7` ≈ 12343초 (섬 1시간 ≈ 현실 8분 34초) | 상수 |
| `estate.clock_epoch` | 새 게임을 시작한 기기 시각 (unix 초) | **쓴다** |
| `island_day` | `1 + ((now - clock_epoch) * 7) / 86400` — 정수 나눗셈 | 안 쓴다 (파생) |
| `estate.last_settled_day` | 마지막으로 정산을 마친 `island_day` | **쓴다** |

날짜를 저장하지 않는 이유는 §1 과 같다. 기준점과 기기 시계, 둘이 있으면 날짜가 나온다. 저장한 날짜를 같이 두면 어느 쪽이 정본인지 알 수 없다.

- 날짜는 시계에서 나온다. 기기 시계를 뒤로 돌리면 날짜도 줄고, `last_settled_day` 에 못 미치므로 정산이 쉰다 (재정산은 없다).
- 기기 시계를 앞으로 당기면 날짜가 뛰고 정산은 한 번 돈다. 그 뒤에도 정산은 `last_settled_day` 를 넘을 때만 돌기 때문에, 시계를 되돌려도 같은 날을 두 번 정산하지 않는다.
- `last_settled_day` 가 없는 세이브는 불러올 때 계산값으로 채운다. 필드 추가이므로 `schema` 를 올리지 않는다 (§5).
- 오프라인에도 시계는 간다. 다만 정산은 돌지 않는다 (4-2).

### 4-2. 정산 — 하루에 한 번, 밀린 날은 건너뛴다

1. 접속 중 `island_day` 가 `last_settled_day` 보다 커지면 그날 정산을 **한 번** 돌리고 `last_settled_day = island_day` 로 둔다.
2. 여러 날이 한꺼번에 지났으면(미접속·절전·시계 변경) **한 번만** 돌고 지난 날은 건너뛴다.
3. 정산 직후 저장한다 (§6).

2번이 이 절의 결정이다. 21일치를 몰아 정산하면 세금·수확·인구증가가 적립되고, 식량 소비·유지비·아사가 몰아 부과되면 손실이다. GDD 04 §3.3 "미접속 기간은 수확 공백일 뿐 — 손실·적립 없음"과 §3.13 "접속보너스 없음"이 둘 다 금지하는 일이다. 그래서 **미접속 중에는 아사·파업 판정도 돌지 않는다** — 지속 일수 카운터가 멈추고 돌아온 날부터 다시 센다.

### 4-3. 정산이 하는 일 (2026-10-24)

한 번의 정산이 하루치를 다음 순서로 처리한다. 새 수치를 코드에 두지 않고 `data/estate.json` 에서 읽는다 (ADR 0002).

| 항목 | 식 | 데이터 |
|---|---|---|
| 채집팀 수확 | 팀 수(소환제단 Lv) × `base_yield` × (1+층/50) × 민심 배율 | `gathering` |
| 영웅 일과 | 고른 일의 몫(팀 수확 ÷ `team_size`) + 생활 태그·각인 | `gathering` · `WORK` |
| 세금 | 인구 × `gold_per_pop_per_island_day` | `tax` |
| 유지비 | 가동 시설 레벨 합 × `maintenance_gold_per_level_per_island_day` | 시설 `initial_level` (건설이 없으므로 초기 가동분만) |
| 식량 소비 | 인구 × `consumption_per_pop_per_island_day` — 보유분까지만 | `food` |
| 인구증가 | 인구 × `natural_growth_rate_per_island_day` × 계절 `natural_growth_mul`, 상한에서 멈춤 | `population` · `farming.seasons` |
| 아사 | 식량이 모자란 날이 `starvation_after_island_days`(3) 이어지면 그날부터 인구 × `starvation_pop_loss_pct`(−2%) | `food` |
| 민심 | 계절이 바뀌는 날 `morale_delta` 만큼 한 번 (겨울 −5) · 0~100 클램프 · 채집 수확 ×(1 + (민심−50)÷50 × 0.20) | `morale` · `farming.seasons` |
| 지갑 | 세금 − 유지비. 잔고는 0 아래로 내려가지 않고, 모자란 유지비는 로그로 남긴다 | — |

- 인구 상한은 **S1 60 고정**이다. 섬 확장(`expansion_cost`)이 아직 없어 스테이지를 올릴 수 없다. 침상 상한은 주택 상태가 붙을 때 `min` 으로 더한다 — 초기 S1 은 스테이지 60 = 침상 60 이라 지금 차이가 없다.
- 식량이 모자라면 먹은 만큼만 빼고 `식량 N 모자람` 을 남긴다. 3일째부터는 `아사 — 인구 -N` 이 붙는다. 먹이면 연속일은 0으로 돌아간다.
- 민심 −5 는 **층 클리어**에서 돈다 (`FonsEstate.note_floor_cleared` — `main.gd` 가 다음 층에 성공할 때 부른다). 04 §3.4 가 민심(층)과 아사(섬일) 주기를 나눠 두었기 때문이다.
- **파업도 층 단위다** (`note_floor_cleared` 안에서 센다). 민심이 `strike_below`(20) 미만인 층이 `strike_after_floors`(3) 이어지면 `strike_floors`(5)층 동안 전 생산이 멈춘다 — 채집팀 수확·영웅 일과 둘 다 0 이고, 정산은 그대로 돌아 식량이 줄어든다. 수치는 `morale_unrest` 에서 읽는다.
- **파업 뒤 회복**: 파업을 겪은 영지는 식량이 남아 있으면 층마다 민심 +`recovery_per_floor`(5), 기준 민심 `morale.initial`(50)에서 멈춘다 (04 §3.14 "파업 후 식량흑자 시 +5/층"). 식량이 바닥인 층은 회복 대신 −5 가 먼저다. 파업 중에는 오르지 않는다 — 정지 중에 오르면 정지가 무의미해진다.
- 식량만 많다고 민심이 오르지는 않는다 — 회복은 파업의 구제이고, 평시 상승은 칙령·게이트 승리(미구현) 몫이다.
- **불만 게이지**는 저장하지 않는다 — `unrest_floors` 에서 그때그때 계산한다 (`FonsEstate.unrest`). 민심이 `enter_below`(25) 미만이면 HUD 에 게이지가 뜨고, `warn_below`(15) 이하면 경고색으로 바뀐다. 게이지가 세는 것은 파업까지 남은 연속 층이고, 파업 중에는 감춘다 (HUD 가 `파업 N층` 을 이미 말한다).
- 정산 결과는 영지 로그에 `섬 N일` · `세금 +N G · 유지비 -N G` · `식량 -N · 남은 N` · `인구 N → N` · `아사 — 인구 -N` · `민심 N → N` 으로 남고, 메인 루프가 같은 줄을 화면 로그에 붙인다.

### 4-4. 파생 타이머

- 채집 쿨·농사 성장은 **남은 초를 저장하지 않는다.** 시작 시각(`harvested_at`·`planted_at`)만 남기고 경과는 시계에서 센다. 오프라인이면 쿨이 지나 있으므로 돌아와 바로 수확할 수 있다 — "깬 시점부터 24h" 폐기(§3.3, 2026-09-14)와 같은 동작이다.
- 계절도 섬일에서 파생한다 — 90섬일이 한 계절, 365섬일이 한 해 ([ADR 0009](../adr/0009-season-on-island-days.md)). `estate.json` 의 `months` 표기는 폐기됐고 `island_days` 범위를 쓴다. 그래서 저장하지 않는다.
- 낮밤(18~6시)은 연출뿐이므로 시계에서 파생한다.
- 프레임·턴 누산값은 저장하지 않는다. `saved_at` 만 남기고 경과는 `clock_epoch` 에서 다시 센다.

### 4-5. `FonsDay` 와의 관계

`FonsDay` 는 **층 하나 안의 아침·낮·저녁**이다 (`godot/core/day.gd` 주석). 섬일과 단위가 다르므로 세이브에 `day` 정수를 넣지 않는다.

- 층은 시작에서 다시 시작하고 전투 도중은 저장하지 않는다 (§6). 그래서 `FonsDay` 는 저장 대상이 아니다 — 불러온 뒤 층 시작에서 새로 만든다.
- 둘은 서로를 기다리지 않는다. 섬일 정산은 영지 시계가, 층 하루 루프는 층 진행이 부른다.
- GDD 04 §3.2 의 "기준 페이스 2.0층/일 (100층 = 50섬일)" 은 진행 속도 기준이지 규칙이 아니다. 층 수로 날짜를 계산하지 않는다.

## 5. 버전과 마이그레이션

| 규칙 | 내용 | 근거 |
|---|---|---|
| 올리는 때 | 이름이 바뀌거나 뜻이 달라질 때만 | 원본은 v6→v7(성격), v7→v8(AI), v12→v13(종점 키워드)에서만 올렸다 (원본 대조) |
| 올리지 않는 때 | 필드 추가. 기본값으로 채운다 | GDD 04 B-10 "은행 필드 없는 구세이브 — 마이그레이션 불요" (원본 대조) |
| 형태 | `{schema: N}` 하나. `from_vN(data)` 함수 하나 + 고정 사전 하나 | 함수와 시험편이 1:1 이어야 빠뜨리지 않는다 |
| 금지 | 비어 있는 값을 **추정해서** 채우기 | v12→v13 은 "미선택 null 유지"였다 (원본 대조) — 모르는 것은 모르는 채로 둔다 |
| 미래 | 더 새 `schema` 는 거부 | 모르는 필드를 버리면 조용한 손실이다 |

## 6. 저장 시점

| 시점 | 이유 |
|---|---|
| 소환 결과 확정 직후 | 잃으면 티켓이 사라진다 |
| 층 클리어(미션 완료) 직후 | 원본의 "액션 단위 커밋" 과 같다 (원본 대조 — GDD 04 §정화) — `main.gd` 가 `next_floor()` 성공 뒤에 부른다 |
| 섬일 정산 직후 | `last_settled_day` 와 저장분이 같이 움직인다 — 따로 저장하면 정산을 두 번 한다. `main.gd` 메인 루프가 1초마다 시계를 보고, 정산이 돌면 저장한다 |
| 층 하루(아침 → 탐험 → 회복) 종료 직후 | HP·영지 저장분이 한 덩어리다 |
| 타이틀에서 저장/종료 | 사용자가 명시적으로 멈출 때 |
| 새로 시작 확정 | 확인창에서 본파일·임시·백업을 지운 뒤 새 런을 연다 — 백업을 남기면 `load_payload` 가 옛 런을 되살린다 |
| 창 닫기 (`NOTIFICATION_WM_CLOSE_REQUEST`) | 마지막 저장이 없으면 층 하나를 잃는다 |

**전투 도중은 저장하지 않는다.** 반쯤 진행한 턴을 복원하면 난수 순서가 어긋나 같은 판이 아니게 된다.

"하루"가 둘이라 이름을 갈라 쓴다. **섬일**은 영지 정산 주기(§4), **층 하루**는 `FonsDay` 의 아침·낮·저녁 루프다. 저장 파일에 들어가는 것은 섬일뿐이다.

## 7. P5-1 범위와 완료 정의

### 범위

1. `godot/core/save.gd` — `to_dict(state)` · `from_dict(dict)` · `migrate(dict)` · `SCHEMA`
2. `godot/autoload/save_manager.gd` — `save(slot)`, `load(slot)`, `backup()`, 손상 처리
3. `FonsRunState` · `FonsEstate` · `GameState` 에 `to_save()`/`from_save()` 추가 — `FonsEstate` 는 `clock_epoch`·`last_settled_day`·`stores`·`population`·`morale`·`shortage_days`·`strike_floors_left`·`unrest_floors`·`recovering` 만 낸다 (§4). `FonsFieldState` 는 넣지 않는다: 필드 좌표·조우 배치는 층 시작에서 다시 만들고, 전투 도중은 저장하지 않는다
4. 타이틀 화면에 "이어하기 / 새로 시작" 두 줄 (UI 문구는 [UI_문구_규칙](../l10n/UI_문구_규칙.md)). 세이브가 있으면 새로 시작 앞에 확인창을 둔다
5. GUT 테스트 8종 (§8) — 구형 `schema`·더 새 판·손상 파일 포함

### 완료 정의

- 새 런을 10층까지 진행 → 저장 → 앱 재시작 → 불러오기 → **층·HP·각인·XP·연계가 같은 값**이고, 다음 층 결과가 저장 전과 같다 (같은 시드·같은 난수).
- 파일을 반으로 자른 뒤 불러오기 → `.corrupt-*` 파일이 생기고, `.bak` 으로 복구되거나 새 게임이 열린다. 원본 파일은 지워지지 않는다.
- `schema` 99 파일 → 읽지 않고 안내한다. 파일 크기·내용이 바뀌지 않는다.
- 저장 파일에 §1 의 "저장하지 않는 것" 목록이 **하나도 없다** (키 화이트리스트 검사).
- 세이브를 3섬일 넘게 두고 불러오면 정산이 **한 번만** 돌고, 식량 소비·유지비가 밀린 날만큼 몰리지 않는다.

## 9. 하지 않는 것

- **클라우드 동기화·다중 기기** — 로컬 단일 파일이면 충분하다. 필요해지면 파일 위에 얹는다.
- **암호화·변조 방지** — 싱글 플레이 로컬 세이브다. 넣어도 지킬 것이 없고, 잃으면 복구만 어려워진다.
- **전투 중 스냅샷** — 난수 재현이 깨진다 (§6).
- **날짜 정수 저장** — 시계와 두 정본이 된다 (§4).
- **오프라인 정산·몰아 정산** — 적립도 손실도 금지다 (§4-2).
- **전체 스냅샷 저장** — ADR 0008 에서 버린 안이다.
- **자동 저장 세대 여러 개** — `.bak` 한 세대면 충분하다. 세대를 늘리면 어느 것이 정본인지 흐려진다.
