# 생태 시뮬 근거 — 출현표와 먹이그물을 어떻게 검증하나 (2026-10-26)

[생태_출현표](생태_출현표.md) §6 이 "그물의 개체수 역학(07 §11 로지스틱·로트카-볼테라)은 별개"로 남겨 둔 자리를 메우려고 외부 자료를 읽은 기록이다.
이 문서는 **참고자료**지 정본이 아니다. 시뮬에 값을 넣기 전에 `tools/tracked_numbers.json` 을 먼저 고친다 (AGENTS §1·§4).

## 1. 출현표를 데이터로 두는 방식 — 자격과 비중을 나눈다

확인한 게임·문서는 모두 **① 자격 필터 → ② 선택 비중 → ③ 동시 개체·무리 크기 → ④ 등급 계층** 순으로 갈라 둔다.

| 게임·문서 | 데이터로 두는 것 | 읽을 때 주의 |
|---|---|---|
| [Minecraft Bedrock spawn_rules](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/spawnrulesreference/examples/spawnrulescomponents/spawn_rules?view=minecraft-bedrock-stable) | 바이옴 필터 · 높이 필터 · 밝기·난이도·거리 · `weight` · 밀도 상한 · 무리 | `weight` 는 **같은 출현 풀 안의** 상대 비중이다 |
| [Valheim — Jötunn SpawnConfig](https://valheim-modding.github.io/Jotunn/api/Jotunn.Configs.SpawnConfig.html) | 바이옴 · 고도·해저 깊이 · 최소·최대 레벨 · 무리 크기 · 최대 동시 개체 · 낮/밤 · 시도 간격 | 모딩 API 문서다 — 게임 내부 구현의 증거는 아니다 |
| [RimWorld 바이옴 모딩](https://rimworldwiki.com/wiki/Modding_Tutorials/Biomes) | 바이옴별 `wildAnimals` 목록 · 개체 가중치 · `animalDensity` | 수치 온도 밴드가 일반 출현 필터인지 **확인 못 함** |
| [Dwarf Fortress Creature token](https://www.dwarffortresswiki.org/index.php/Creature_token) | `BIOME` · `LARGE_ROAMING` · `FREQUENCY` · `CLUSTER_NUMBER` | `FREQUENCY` 를 단순 가중치로 옮겨 읽으면 안 된다 |

- **등급 선택과 종 선택은 2단계로 나눈다.** 등급 가중치를 그 등급의 모든 종에 곱하면 **종 수가 많은 등급만 부풀어 오른다.**
- 생존 가능 범위(하드 필터)와 출현 적합도(소프트 필터)를 구분한다.
- 우리 `FonsEncounter` 는 이미 habitat 교집합 · 온도 밴드 · 3~5종 · `target_tier` 를 갖는다 — 위 뼈대와 같다. 뽑는 방식은 등급 가중치가 아니라 **중심 등급과의 거리 정렬**이라 위 함정에 걸리지 않는다. 지금 값을 더 넣을 자리는 없다.

## 2. 먹이그물 검증 — 지표를 하나로 두지 않는다

- 로트카-볼테라를 차분식으로 돌려 개체수를 보는 공개 사례가 있다 ([SDU 강의](https://jonesor.github.io/BB512_Book/lotka-volterra-predator-prey-dynamics.html) · [SERC 스프레드시트 활동](https://serc.carleton.edu/sp/ssac/examples/14327.html)). 기본형에는 수용력·기능반응·분해자가 없어 확장이 필요하다.
- 안정성은 한 축이 아니다 — [PNAS 연구](https://pmc.ncbi.nlm.nih.gov/articles/PMC6926024/)는 펄스 교란 반응 · 지속 교란 민감도 · 붕괴 임계점까지의 거리를 다른 차원으로 나눠 27개 지표를 비교했다.
- **사체 경로를 먹이망에 넣는 것**이 안정성 평가에 중요하고, 포식자·피식자 biomass 비율을 간이 지표로 쓸 수 있다 ([2025 수생 먹이망 연구](https://pmc.ncbi.nlm.nih.gov/articles/PMC12334362/)).

시뮬에서 볼 것 (07 §8 로지스틱·10% 법칙의 검증 축):

| 볼 것 | 재는 법 |
|---|---|
| 지속성·멸종 | 충분히 긴 초기 구간 뒤 개체수가 임계 이하인 종의 비율 |
| 폭증·자원 고갈 | 개체수 ÷ 수용력, 먹이 소비량 대비 재생산량 |
| 포식–피식 균형 | 피식자 생산량 대비 포식자 섭취·번식, biomass 비율 |
| 변동성 | 정착 구간의 평균·표준편차 (오르내림 자체는 실패가 아니다) |
| 교란 후 회복 | 사냥·가뭄·포식자 제거 뒤 기준 상태로 돌아오는 시간과 폭 |
| 멸종 연쇄 | 종을 하나씩 빼며 2차 멸종 수와 전환 시점 |

**임계값을 문헌에서 가져오지 않는다** — 문헌도 "게임 스케일에 맞춰 정하라"고 적는다. 검사로 FAIL 을 걸 값은 `tools/tracked_numbers.json` 을 먼저 고친다.

## 3. 08 §4 의 다섯 경로 — 근거가 있는 것과 없는 것

| 경로 | 근거 | 정적 시뮬에서의 자리 |
|---|---|---|
| 청소 (사체→청소부) | 있음 — 청소동물은 사체를 먹고 에너지를 옮긴다 ([LibreTexts 먹이그물](https://bio.libretexts.org/Courses/CT_State_Northwestern/General_Ecology_Ecology/Chapter_19%3A_Food_Webs/19.1%3A_Introduction_to_and_Components_of_Food_Webs) · [ASU EcoChains](https://askabiologist.asu.edu/games-and-simulations/ecochains-coral-futures)) | 에너지 흐름 |
| 부식 (분해→토양) | 있음 — 분해자가 영양분을 순환시킨다 (같은 교재) | 에너지 흐름 |
| 기생·약탈 | 기생은 있음 — 숙주를 한 번에 소비하지 않고 건강·사망률에 작용한다 ([Sukhdeo 2012](https://pmc.ncbi.nlm.nih.gov/articles/PMC3523981/)) | 에너지 흐름 (알훔치기는 용어 근거 **확인 못 함**) |
| 에테르 (`soul`·`mana`) | **확인 못 함** — 게임 고유 경로다 | 별도 계층 (물질 자원과 섞지 않는다) |
| 담당자 스위치 (`activity`) | **먹이 경로로 본 사례 확인 못 함** — 플레이어 관리·교란 계층에 가깝다 ([Eco 동물](https://wiki.play.eco/en/Animals) · [Wild Willows](https://wildwillows.app/)) | 별도 계층 (주간·야행성 분업은 전투·출현 쪽) |

이 절은 08 §4 를 고치자는 것이 아니다 (`docs/gdd/` 는 원본 문면 — AGENTS §3). **시뮬에서 다섯 경로를 같은 무게로 다루지 않는다**는 근거다.

## 4. 지금 있는 것과 없는 것

| | 있는 것 |
|---|---|
| 구조 | `sim/foodweb.py` E-1~E-7 — 참조·쌍방 정합·고아·순환·0간선 바이옴 (통과) |
| 출현 | `FonsEncounter` 편성 규칙 + `godot/tools/ecology_report.gd` 130층 표 |
| 개체수 입력 | `data/ecology_energy_channels.json` — 바이옴별 근원자원 `K`·`r` · 채널 4 |

없는 것은 **사냥·미션 뒤 개체수가 바뀌고 그것이 다음 층 편성으로 돌아오는 계산**이다 (07 §10-3 "미션 수행은 생태 상태를 변경 → 다음 층 재방문 시 반영"). 만들 때 쓸 지표는 §2 표, 나눌 계층은 §3 이다.

## 5. 한계

- 조사한 자료는 게임별 구현 사례와 생태 모형·교육용 시뮬레이션이다. 탐험·생존 게임 업계가 같은 출현표 형식이나 같은 검증 절차를 쓴다는 근거는 없다.
- 다섯 경로 분류는 이 저장소의 설계다. 표준 생태학 분류로 확인된 것은 청소·분해·기생 셋뿐이다.
