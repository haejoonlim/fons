# 층간 회복 규칙 — 회복으로는 한 층도 더 못 간다

측정 2026-10-28 · 근거 [chain_report.gd](../../godot/tools/chain_report.gd) `--heal` (이번에 추가) · `godot/core/field_state.gd` `next_floor` · 선행 [111-120_이벤트_전환_비용.md](111-120_이벤트_전환_비용.md) §5 · [101-110_벽_정체.md](101-110_벽_정체.md) §5

필드는 층 사이에 HP 를 회복하지 않는다. 그 조건의 사슬에서 ★5 는 101, ★7 은 106 에서 멈춘다. 회복을 넣으면 어디까지 가는지, 최소 회복률이 얼마인지 쟀다. 답은 **회복률이 얼마든 달라지지 않는다**다.

## 1. 결론

1. **회복률 0·10·25·50·100% 어느 값도 도달을 1층도 바꾸지 않는다.** ★5 는 전부 101 에서, ★7 은 105·105·101 에서 멈춘다(정지 이유까지 동일).
2. **회복은 살아 있는 영웅의 HP 만 채운다.** 106 앞에서 파티는 이미 2/5·3/5 다. 죽은 영웅은 안 돌아오므로, 최대 HP 의 60% 를 만피로 채워도 5인분이 되지 않는다.
3. **회복이 아니라 층 자체가 벽이다.** 만피 5/5 로 106 에 새로 들어가도 ★7 은 무·패·무다(§5). 106 은 누적 피해로 막히는 층이 아니다 — [101-110_벽_정체.md](101-110_벽_정체.md) §5 의 2.6배 단차와 같은 결론이다.
4. **그래서 "★5 가 111 에 닿는 최소 회복률"은 없다.** 어떤 비율로도 못 닿는다. 회복을 게임 규칙으로 넣는 것은 상층 도달을 못 늘리고, 101~105 를 더 쉽게 만들 뿐이다.
5. **필요한 것은 회복이 아니라 106~110 완화 아니면 부활 규칙이다.** 둘 다 이 문서 범위 밖의 결정이다 — 106 완화 후보는 [101-110_벽_정체.md](101-110_벽_정체.md) §7.

## 2. 측정 조건

- `chain_report` · 101~125 일반 조우 + 126·127·128·130 문지기 · 5인 · 층 기대 레벨 · 101 은 만피 시작 · 턴 상한 500.
- `--heal=<0~1>`: **층 승리 직후, 살아 있는 영웅만** `hp += round(maxHp × 비율)`, `maxHp` 상한. 기본 0 = 현행.
- 등급 5·7 × 시드 1·2·3 × 회복률 0·0.10·0.25·0.50·1.00 = **30칸**.
- 접촉 0 만 친다(필드는 층당 3곳). 그래서 이 사슬은 필드보다 관대하다 — 실제 도달은 이 표보다 낮다.
- 126~130 은 데이터상 `noCombat` 이라 일반 조우로 재면 0턴 가짜 승리가 된다. **문지기로만** 쳤고, 129(문지기 없음)는 목록에서 뺐다.

|---:|:-:|---|---|---|
| 0 | ★5 | 없음 (101 enemy) | 없음 (101 enemy) | 없음 (101 draw) |
| 0 | ★7 | 105 (106 draw) | 105 (106 enemy) | 101 (102 draw) |
| 0.10 | ★5 | 없음 (101 enemy) | 없음 (101 enemy) | 없음 (101 draw) |

| 0.25 | ★5 | 없음 (101 enemy) | 없음 (101 enemy) | 없음 (101 draw) |

- "없음"은 시작 층(101)에서 한 층도 못 넘겼다는 뜻이다. 101 에서 5인 전멸 또는 500턴 무승부.
- **30칸이 전부 같다.** 회복률은 도달에 영향이 0 이다.
- ★7 시드 1·2 는 101~105(정상)를 이기고 106(빙해)에서 멈춘다. 시드 3 은 102 에서 이미 500턴이다.

## 4. 회복이 실제로 걸렸다는 증거

`--heal=1.0` · ★7 시드 1 · 101~103 에서 회복량을 찍었다.

| 구간 | 회복량 | 그때 상태 |
|---|---:|---|
| 101 승리 뒤 | **+1,825** | 2/5 생존 · HP 118,852/198,629 — 이미 자기 최대에 가깝다 |
| 102 승리 뒤 | **+40,188** | 2/5 생존 · HP 40,301 → 80,489 (생존 2인의 최대) |
| 103 승리 뒤 | +39,497 | 2/5 생존 · 같은 이유 |

- 회복은 동작한다. 문제는 **채울 대상이 2명뿐**이라는 것이다.
- 2인 만피로는 106 을 못 넘고, 죽은 3인은 회복으로 안 돌아온다. 그래서 회복률을 올려도 정지 층이 그대로다.

## 5. 대조 — 만피 5/5 로 106 에 들어가도

`--from=106 --to=110 --grades=7 --seeds=1,2,3` (회복 무관, 106 에서 새 파티):

| 시드 | 106 결과 | 생존 |
|---:|---|---|
| 1 | 무 500턴 | 2/5 |
| 2 | 패 165턴 | 0/5 |
| 3 | 무 500턴 | 1/5 |

- **만피로 시작해도 못 이긴다.** 즉 106 은 "앞에서 닳아서" 막히는 층이 아니다.
- 그러므로 회복 규칙은 106 벽에 대해 아무것도 바꾸지 못한다. 바꾸려면 106~110 의 적 화력·HP 를 내리거나(곡선), 죽은 영웅을 되살리는 별도 규칙이 필요하다.

## 6. 역전 — 판정 불가

- 도달이 안 변해 역전도 안 생긴다. 회복을 넣어도 101~130 의 어려움 순서는 그대로다.
- 다만 101~105 는 회복으로 쉬워질 수 있다(2인이 만피로 다음 층). 이 표는 도달만 보므로 그 체감은 안 쟀다.

## 7. 구현 비용

지금 코드에 층간 회복은 없다. 넣는다면 `FonsFieldState.next_floor` 에 5줄 남짓(승리 직후 파티 HP 순회) + `test_field_party.gd` 1건이다.

| 방식 | 바꾸는 자리 | 크기 | 대가 |
|---|---|---|---|
| 회복 규칙 | `field_state.gd` `next_floor` | 5줄 | **도달 +0** — 이 문서의 표 |
| 106~110 완화 | `FonsScaling` 상수 + 분기 | 3줄 | [101-110_벽_정체.md](101-110_벽_정체.md) §7 (106 경계로 자르는 쪽) |
| 부활 규칙 | `field_state.gd` + 정본 결정 | 10줄~ | 죽음을 무르는 규칙은 밸런스가 아니라 설계 결정 |

- 이번에 넣은 것은 **측정 손잡이**(`--heal`)뿐이다. 게임 경로는 회복하지 않는다.
- 회복을 정본으로 넣으려면 "0층 이득"을 먼저 설명해야 한다 — 지금은 넣을 이유가 없다.

## 10. 한계

- 접촉 0 만 친다. 필드는 층당 3곳을 다 쳐야 하므로 실제 도달은 이 표보다 낮다 — 다만 표가 이미 "없음/105" 라 더 낮아질 자리가 작다.
- 101 에서 만피로 시작한다. 실제 런은 1~100 을 지나며 닳은 상태다.
- 시드 3개다. ★7 이 106 을 넘는 시드가 있을 수 있으나, 만피 5/5 로도 106 이 무·패·무라 회복으로 열릴 가능성은 낮다.
- ★5·★7 5인만 쟀다. ★6·4인, 부활·부분 회복(1인 지정)은 안 쟀다.
- 126~130 문지기 경로는 아무 시드도 닿지 못해 실제로 돌지 않았다(코드 경로만 확인).
- 회복의 체감(101~105 가 쉬워지는 정도)은 안 쟀다 — 도달만 쟀다.
