# 셰이딩·조각 수 선택지 (2026-10-26)

계획 §9 에 남은 미결정 둘은 **셰이딩**과 **모듈 조각 수**다. 이 문서는 그 둘을 고를 수 있게 후보·비용·판정 기준을 정리한다. **값을 정하지 않는다** — 고른 값은 [ART_BIBLE](ART_BIBLE.md) "3D 키트" 절에 적는다.

## 1. 셰이딩 — 후보 셋

| 후보 | 무엇이 바뀌나 | 비용 | 되돌리기 | 먼저 확인할 것 |
|---|---|---|---|---|
| **A. 지금 그대로** — 상자는 면 법선, 구·원기둥은 스무스, 지형은 중심차분 | 없음 | 0 | — | 돌·벽 모서리가 뭉개져 보이는지 |
| **B. 부품만 플랫** — 구·원기둥·원뿔까지 면 법선으로. 지형은 그대로 | 생성기 한 곳 | 낮음 (삼각형 수·부품 수는 안 는다) | 생성기를 되돌리고 재생성 | 잎·이끼가 각져 보이는지 |
| **C. 툰** — 밝기 단계로 자르는 셰이더 | 지형·키트·캐릭터 재질 전부 | 높음 (셰이더 + 전 재질) | 셰이더 제거 | `gl_compatibility` 에서 도는지 ([ADR 0004](../adr/0004-renderer-gl-compatibility.md)) |

- **아웃라인은 셋 다 안 넣는다** — 배포 팩에서 기본 아웃라인을 확인하지 못했고([스타일_리서치](스타일_리서치.md) §3), 넣으면 부품마다 외곽선 메시를 하나 더 깔아야 한다.
- C 를 고르면 밝기 단계 수·광원 각도 같은 값이 새로 필요하다. 그런 값은 정한 뒤 `tools/tracked_numbers.json` 을 먼저 고친다 (AGENTS §4).

## 2. 모듈 조각 수 — 후보 둘

| 후보 | 무엇이 바뀌나 | 비용 |
|---|---|---|
| **A. 11부품 유지** | 없음 | 0 |
| **B. 늘리기** — 바닥 변형 + 경계·모서리 조각 | 생성기와 [FonsBiomeKit](../../godot/game/view/view_3d/biome_kit.gd) 배치 규칙 | 배치 규칙이 늘고 검증할 조합이 는다 |

- 업계 공통 조각 수는 확인되지 않았다 ([스타일_리서치](스타일_리서치.md) §4). 외부 수치를 근거로 삼을 수 없다.
- 우리 지형은 **한 장의 높이필드**라 조각 사이 이음매가 없다. 그래서 경계·모서리 조각이 필요한 이유(연결)가 우리에게는 없다 — 남는 판정 기준은 "26바이옴이 서로 다르게 읽히는가" 하나다.
- 늘릴 때도 5유닛 격자는 넘지 않는다 (계획 §9 확정).
- 조각 수와 셰이딩은 따로 고를 수 있다. 둘을 한 번에 바꾸면 시트에서 무엇 때문인지 갈리지 않는다.

## 3. 재는 법

```bash
./.venv/bin/python tools/gen_kit_glb.py --check          # 부품 수·바이트 드리프트 (게이트 kitart)
godot --path godot -s tools/shot_shading_compare.gd       # 셰이딩 후보 A·B·C 대조 (렌더링 필요 — headless 아님)
godot --path godot -s tools/shot_biomes_3d.gd             # 26바이옴 실렌더 (렌더링 필요 — headless 아님)
godot --path godot -s tools/shot_biomes3d_sheet.gd        # 26바이옴 접합 시트 (headless 로도 된다)
./tools/test_godot.sh                                     # 뷰·키트 계약
```

같은 조건으로 두 장을 뽑아 나란히 놓는다. 볼 것은 셋 — ① 시트에서 갈리는 바이옴 수 ② 부품별 삼각형 수 ③ 프레임 시간.

## 3.5 실측 결과 (2026-10-26, 렌더 12장 + 시트 2장)

하네스 [shot_shading_compare.gd](../../godot/tools/shot_shading_compare.gd) 는 게임의 하늘·태양·안개를 그대로 쓰고, 키트 부품 다섯(랜드마크 1 · 높이 2 · 프롭 2)을 **견본대**로 세워 카메라만 고정한다. 필드에 흩어진 프롭을 그대로 찍으면 영웅과 표식이 앞을 가려 세 후보가 같은 그림이 됐다(첫 실행).

| 후보 | 실제로 무엇이 보였나 | 판정에 필요한 것 |
|---|---|---|
| A | 잎·둔덕·바위가 매끈한 그라데이션. 상자(벽·상인방)는 원래 평평 | 기준 |
| B | 구·원기둥이 **면 단위로 갈린다** — 나무 캐노피가 8×5 분할 그대로 각져 보이고, 둔덕·바위 가장자리에 모서리가 생긴다 | 어떤 크기에서 "각져 보인다"고 볼지 |
| C | **`gl_compatibility` 에서 컴파일·렌더된다**(`light()` 안의 밴드). 그늘도 A 보다 밝고 색도 맞았다 (§3.6) | 채택 여부 — 캐릭터·지형까지 덮는가 |

- C 는 **`DIFFUSE_LIGHT`·`AMBIENT_LIGHT` 를 `fragment()` 에서 못 쓴다** — 4.7 compatibility 에서 `light()` 안에 `AMBIENT_LIGHT` 식별자도 없다. 환경광은 `view._environment` 에서 읽어 uniform 으로 넘긴다.
- 그 조명 모델(밴드·태양/환경 비율·노출·광택)은 이제 **뷰 계층이 갖는다** — [toon_shade.gd](../../godot/game/view/view_3d/toon_shade.gd) `FonsToonShade`. 하네스는 그 모듈을 불러서 잰다. 채택은 `view_3d` 가 재질을 깐 뒤 `apply()` 한 줄을 부르면 된다.

## 3.6 C 의 조명 모델 — 정한 값과 측정 (2026-10-26 · **구 모델 기준**)

> 2026-10-27 에 모델을 고쳤다(π 제거·NdotL 게이트·알베도 선형화 — §3.7). 아래 표와 값은 **그 전 모델**에서 잰 것이라 지금 코드에 그대로 대응하지 않는다. 재보정 전까지는 참고용이다.

사양은 [toon_shade.gd](../../godot/game/view/view_3d/toon_shade.gd) `FonsToonShade` 가 갖는다. **채택하면 `tracked_numbers.json` 을 먼저 거친다** — 지금은 후보 모듈 안의 값이다.

| 값 | 결정 | 근거 |
|---|---|---|
| 밴드 문턱 | **0.45 · 0.72** | 이 조명(태양 0.99/1.23 · 환경 0.95/0.85 — plains/ruins, 2026-10-27 실측)에서 세 단이 부품에 다 나오는 폭. 더 좁히면 단이 하나로 몰리고 넓히면 경계가 안 보였다 |
| 중간 단 | **0.82** | 문턱 사이를 0.82 로 두어 그늘→중간 간격이 눈에 띄게 |
| 그늘 바닥 | **0.60** | 0 으로 두면 그늘을 환경광으로만 메워야 해서 돌이 주황으로 물들었다 |
| 환경광 배율 | **1.6** | 1.2 → 3.0 으로 올려도 평균이 0.164 → 0.166 밖에 안 움었다(실측) — 그늘은 밴드 바닥값이 민다 |
| 태양 노출 | **1.1** | 밴드 셰이더는 A 보다 어둡다. A 와 같은 화소의 평균이 맞는 값 |
| 넓은 광택 | **0.001** | 태양 색(푸른 `#d8e5ff`)을 **albedo 무관하게** 더하는 항. 이 항이 색을 맞춘다(아래 표) |
| 색 균형 | **1.0 (채널별 보정 안 함)** | 광택 항만으로 두 바이옴 오차가 들어와, 채널 보정을 안 걸었다 |

**색이 틀어진 원인은 광택 항이었다.** 밴드 셰이더는 태양 항을 `albedo` 에만 곱한다. 표준 재질의 하이라이트는 albedo 를 안 곱하고 태양 색을 그대로 반사하므로, 그 항이 없으면 **파랑 albedo 가 낮은 잎·풀에서 파랑이 사라진다**. 태양 색·`source_color` 이중 변환은 시험해서 원인이 아님을 확인했다.

보정 표 (2026-10-26 23:0x · 노출 1.10 고정 · 시트 원본 1280×720 · **셰이딩이 바뀐 화소만** 골라 잰 값 · sRGB · 《오차》는 A 와 C 의 평균 색 거리):

| 넓은 광택 | plains 색 (A 0.148 0.214 0.138) | 오차 | ruins 색 (A 0.280 0.283 0.283) | 오차 |
|---|---|---|---|---|
| 0.0000 | (0.104 0.203 0.086) | 0.069 | (0.311 0.294 0.257) | 0.042 |
| 0.0010 | (0.140 0.223 0.136) | **0.013** | (0.323 0.312 0.281) | 0.052 |
| 0.0030 | (0.193 0.261 0.200) | 0.089 | (0.350 0.341 0.324) | 0.100 |

- **광택 항은 세기가 예민하다** — `SPECULAR_LIGHT` 를 직접 쓰면 엔진 스케일이 커서, 0.12 로 두면 화면이 통째로 탔다(평균 0.18 → 0.67). 0.001 눈금으로 맞춰야 한다.
- **모듈로 옮긴 뒤 재현했다** (2026-10-27) — 조명 모델을 `FonsToonShade` 로 빼고 하네스가 그 모듈을 부르는 경로로 다시 돌려도 같은 표가 나왔다(plains 오차 0.013 · ruins 0.052 · A 평균 0.212/0.286). 계약은 `tests/unit/test_toon_shade.gd` 가 잠근다(답기·되돌리기·값 반영·사라진 노드).
- **남은 오차** — 이 시트에서 plains 0.013 · ruins 0.052. ruins 는 A 가 이 실행에서 밝아져(0.274 → 0.286) 광택 0 이 더 맞았다. **A 는 지금 다른 작업이 같이 고치는 중**이라 실행마다 값이 움직인다 — 표의 A 와 C 는 같은 실행에서 잰 값이다.
- **그늘은 여전히 A 보다 밝다** — p10 이 plains 0.179 vs 0.108 · ruins 0.287 vs 0.223. 이건 후보 C 의 **의도된 차이**다(그늘에서도 태양을 조금 받는다) — 색이 아니라 밝기 분포의 차이다.
- **밝은 면은 아직 조금 어둡다** — p90 plains 0.224 vs 0.272 (밴드 위쪽이 1.0 이라 더 못 올린다. 올리려면 태양 노출을 더 키워야 하는데 그러면 평균이 넘친다).

## 3.7 채택 시도 (2026-10-27) — 모델 결함 다섯을 찾고 되돌렸다

등록소에 7값을 올리고 `view_3d` 가 키트를 덮게 해서 실제 필드를 찍으며 하나씩 고쳐 나갔다. 결함을 다섯 찾았고, 고친 뒤에는 **보정이 처음부터 다시 필요해졌다.** 연결은 되돌렸다 — 지금 `view_3d` 는 툰을 안 쓴다.

### 찾은 결함 (전부 렌더 실측)

1. **태양 항에 `x PI x gain`** — π 를 곱하면 밝은 면이 ×3.8 로 넘친다. 실측: 키트 관목 A(0.710 0.686 0.349) → C(**1.000 1.000** 0.439). π 를 뺐다.
2. **밴드 바닥값이 NdotL 을 대신했다** — `band` 가 항상 0.6 이상이라 **태양을 등진 면도 60%** 를 받았다(전반 2배). `step(ndl)` 로 게이트했다. 그늘은 환경광이 맡는다.
3. **`albedo_color` 는 sRGB 인데 그대로 선형으로 들어갔다** — 키트 부품 11개의 재질을 직접 읽어 확인(정점색 없음, 알베도 `5c6b3a` 같은 sRGB hex). 셰이더에서 직접 변환한다.
4. **정점색도 sRGB** — 같은 이유로 밝은 정점색이 1.0 에 붙었다. 셰이더 언어에 `srgb_to_linear` **내장이 없다**(쓰면 컴파일이 통째로 실패: `No matching function found for: 'srgb_to_linear'`) — 식을 직접 둔다.
5. **`source_color` 힌트는 런타임에 안 먹는다** — 달아도 `set_shader_parameter` 로 넣은 값은 그대로다(실측: 화소 변화 0). 힌트에 기대면 안 된다.

### 고친 뒤 재 측정 — 보정이 무효가 됐다

하네스([shot_shading_compare.gd](../../godot/tools/shot_shading_compare.gd))로 광택을 훑은 값. A 는 같은 실행에서 잰 값이다.

| 광택 계수 | plains C 평균 (A 0.213) | ruins C 평균 (A 0.287) | 색 오차 (plains) |
|---|---|---|---|
| 0.000 (지금 상수) | 0.048 | 0.066 | 0.200 |
| 0.20 | 0.622 | 0.710 | 0.685 |
| 0.35 | 0.798 | 0.901 | 0.950 |
| 0.50 | 0.881 | 0.964 | 1.072 |

- **광택 0 은 3배 어둡고, 0.2 만 올려도 3배 밝다** — 한 계수로 중간을 못 잡는다. 광택 항이 더해지는 방식(`SPECULAR_LIGHT +=`)이 엔진 광택과 스케일이 달라서다. 다음 사람은 이 항의 스케일부터 잡아야 한다.
- **§3.6 의 표는 구 모델(π·바닥값·비선형 알베도) 기준이다** — 지금 모델에 그대로 쓸 수 없다.
- **지형은 여전히 빠졌다** — srgb 정점색 경로에서 툰은 색은 맞고 밝기가 0.13배다(채널비 0.11/0.17/0.14로 균일). 그래서 지형 재질은 표준 그대로 뒀다.

### 광택 하나로 색과 그늘을 같이 못 잡는다 (2026-10-27 실측)

같은 빌드에서 `TOON` 만 꺼서 대조를 만들고, 같은 좌표를 두 판에서 읽었다.

| 자리 | 툰 끔 | 광택 0.001 | 광택 0.030 |
|---|---|---|---|
| 관목 (밝은 노랑) | 0.761 0.733 0.376 | 0.796 0.608 **0.110** | 0.839 0.671 **0.353** |
| 중경 나무 | 0.196 0.282 0.235 | 0.133 0.204 0.196 | 0.290 0.314 0.353 |
| 먼 바위 | 0.376 0.435 0.537 | 0.353 0.416 0.522 | 0.388 0.451 0.557 |
| 통 (material_override) | 0.718 0.569 0.263 | 그대로 | 그대로 |
| 풀 (지형, 표준 재질) | 0.424 0.541 0.380 | 그대로 | 그대로 |

- **광택 0.03 이 관목 색을 맞춘다**(파랑 0.110 → 0.353, 툰 끔 0.376). 그런데 **시트에서 그늘진 키트가 검게 죽는다** — 왼쪽 큰 나무·바위가 거의 검정이 된다. 광택 항은 albedo 를 안 곱하므로 밝은 면은 살리고 어두운 면은 환경광만 남겨서다.
- **광택을 낮추면 색이 탁해지고, 올리면 그늘이 죽는다** — 두 값(광택·환경광 배율)을 **함께** 맞춰야 한다. 이번에는 못 했다.
- **통은 툰이 안 덮인다** — `material_override` 를 쓰는 메시라서다(같은 값 유지). 전 재질을 덮으려면 `_material`·`_avatar_material` 팩토리부터 고쳐야 한다.
- 이 시도로 연결은 다시 되돌렸다. 남은 작업은 광택과 환경광 배율의 2값 맞춤 하나다.
- **프롭 커버리지도 일정치 않다** — 키트는 surface override 라 덮이지만 `material_override` 를 쓰는 메시(유닛·바닥판·일부 프롭)는 안 덮인다. 전 재질을 덮으려면 `_material`·`_avatar_material` 팩터리부터 바꿔야 한다.

## 3.8 2값 맞춤 시도 (2026-10-27) — 확산광이 안 더해진다

§3.7 이 남긴 "광택과 환경광 배율을 함께 맞춘다"를 하려고, 하네스가 환경광 배율까지 훑게 고쳤다
(`CALIBRATION` 이 `[노출, 광택, 환경광]` 셋, 판마다 p10·p90 을 같이 찍는다). 격자를 돌린 결과는
**값을 맞출 대상이 없는 표**였다.

| 광택 | 환경광 | C 평균 (A 0.213) | p10 (A 0.108) | p90 (A 0.272) | 색 오차 |
|---|---|---|---|---|---|
| 0.000 | 1.0 | 0.051 | 0.039 | 0.051 | 0.227 |
| 0.001 | 1.0 | 0.067 | 0.041 | 0.073 | 0.197 |
| 0.002 | 1.0 | 0.082 | 0.041 | 0.092 | 0.175 |
| 0.002 | 1.8 | 0.082 | 0.041 | 0.092 | 0.174 |
| 0.003 | 1.8 | 0.094 | 0.041 | 0.108 | 0.156 |

- **환경광 배율이 화소를 안 움직인다** — 1.0 → 2.6 → **10.0** 으로 올려도 평균이 0.066 그대로였다(재질에는 ambient (0.18 0.20 0.24)·fill 1.0 이 실제로 들어가 있는 것을 확인).
- **p10 이 광택에도 안 움직인다** — 0.039~0.041 로 고정. 그늘은 어느 항도 안 받고 있다.
- **반응하는 항은 광택 하나** — 광택 0.001 당 평균이 약 0.013 오른다. 알베도를 안 곱하는 항이라 색도 그것만 따라온다(오차 0.227 → 0.156).
- **알베도 전달은 문제가 아니었다** — 덮은 재질의 알베도를 찍어 보니 나무 잎 `3d5a30`·바위 `6f6f68` 이 그대로 들어 있었다. 그래도 부품이 검게 나온다(그림 참조).
- **`light()` 안의 `ALBEDO` 가 0 인 것을 의심해 varying 으로 알베도를 직접 넘겼다** — 화소가 0.066 → 0.067 로 사실상 그대로. 원인이 그것도 아니다.

### 판정 — 후보 C 의 `light()` 경로를 접는다

확산·환경광 항은 이 렌더러(`gl_compatibility`, 4.7.2)에서 화면에 거의 안 더해지고,
`SPECULAR_LIGHT` 만 제 크기로 더해진다. 원인을 좁히려고 밝기·알베도·환경광·varying 네 갈래를
재 봤지만 값 조합으로 메울 수 있는 차이가 아니다 — **같은 식의 두 항이 100배 넘게 다른 무게로
들어간다.** 다음 중 하나를 골라야 한다.

1. **`unshaded` + 직접 조명** — 태양 방향·색·환경광을 uniform 으로 받고 `fragment()` 에서 밴드를 계산한다. 크기가 전부 우리 손에 있고 엔진 스케일을 안 탄다. 대신 **실그림자를 잃는다**(그림자 감쇠를 직접 받을 수 없다).
2. **표준 재질을 그대로 쓰고 밴딩만 포기** — A 가 이미 목표 그림이다. 후보 C 의 이점(면이 아니라 밝기 단)을 안 쓰기로 한다.
3. **`forward_plus` 를 견본대에서만 시험** — 렌더러를 바꾸면 `light()` 동작이 다를 수 있다. 다만 §2 의 제약(호환 렌더러)과 어긋나므로 후보 판정용으로만 쓴다.

지금 상태로 `view_3d` 에 연결하지 않는다. 하네스와 모듈은 그대로 두었다 — 위 1번을 고르면
셰이더 본문만 바꿔 같은 격자로 다시 잴 수 있다.

## 3.9 `unshaded` 로 다시 짰다 (2026-10-27) — A 와 맞았다

§3.8 의 진단대로 `light()` 를 버렸다. 셰이더는 `render_mode cull_back, unshaded` 이고, 태양 방향·색·
환경광을 uniform 으로 받아 `fragment()` 에서 밴드를 계산한다. 값 셋(노출·광택·환경광)이 전부
우리 손에 있으니 하네스 격자로 바로 맞출 수 있다.

맞추는 중에 걸린 것 둘 — 둘 다 실측으로 갈랐다.

- **광원 축 부호** — `_sun_dir` 을 반대로 잡으면 `ndl` 이 전부 0 이 되어 태양 항이 통째로 사라진다(화면이 6배 어두워졌다). 태양은 항상 아래로 내려쏘므로 y 부호를 강제한다.
- **알베도 감마** — 이 렌더러는 `unshaded` 의 `ALBEDO` 를 화면까지 그대로 넘긴다(실측: 상수 0.5 → PNG 0.502). 여기서 선형으로 바꾸면 잎 0.24 가 0.05 로 눌려 부품이 검게 죽었다. 감마를 안 건다.

최종 격자 (1280×720 · 셰이딩이 바뀐 화소 · A 는 같은 실행에서 잰 값). 필드에 붙여 보니 노출 0.70 에서 카메라를 등진 프롭이 거의 검었서, 환경광을 더 주는 쪽으로 한 번 더 내렸다.

| 노출 | 광택 | 환경광 | plains 평균 (A 0.192) | p10 (A 0.108) | p90 (A 0.272) | 색 오차 |
|---|---|---|---|---|---|---|
| **0.63** | **0.035** | **2.6** | **0.190** | **0.104** | **0.258** | 0.054 |
| 0.66 | 0.035 | 2.4 | 0.184 | 0.094 | 0.255 | 0.057 |
| 0.70 | 0.035 | 2.2 | 0.180 | 0.083 | 0.255 | 0.060 |

ruins 같은 판(같은 실행):

| 노출 | 광택 | 환경광 | 평균 (A 0.278) | p10 (A 0.207) | p90 (A 0.301) | 색 오차 |
|---|---|---|---|---|---|---|
| **0.63** | **0.035** | **2.6** | 0.324 | 0.303 | 0.351 | 0.097 |
| 0.66 | 0.035 | 2.4 | 0.318 | 0.296 | 0.346 | 0.085 |
| 0.70 | 0.035 | 2.2 | 0.315 | 0.292 | 0.343 | 0.079 |

- **plains 는 사실상 맞았다** — 평균 0.190 vs 0.192 · p10 0.104 vs 0.108. 색 오차도 0.20 에서 0.054 로 내려왔다.
- **고른 값**: `EXPOSURE 0.63 · SPECULAR_GAIN 0.035 · AMBIENT_FILL 2.6`. 등록소에 올렸다.
- **ruins 는 밝게 넘친다**(0.324 vs 0.278 — 16%). 무채색 부품이라 환경광이 더하면 색도 함께 틀어진다(오차 0.097). **바이옴별 배율을 나누기 전에는 여기서 멈춘다.**
- **눈으로 본 판정**: 캐노피에 밴드 두 단이 보이고 바위·폐허 벽의 색이 A 와 같은 대역이다. A 는 매끈한 그라데이션, C 는 면이 갈린 단 — 이게 후보 C 의 의도된 차이다.
- **잃은 것**: **실그림자를 못 받는다**(`unshaded`). 지금 조명은 `shadow_enabled` 를 안 켜므로 지금은 잃는 것이 없다. 나중에 그림자를 켜면 지형이 프롭 그림자를 받지 못한다.

## 3.10 채택 — `view_3d` 가 키트·지형을 덮는다 (2026-10-27)

`view_3d` 가 `FonsToonShade` 하나를 들고 세 곳에서 부른다.

| 부를 때 | 왜 |
|---|---|
| `_apply_palette()` 끝 | 조명·환경광이 바뀌었다 — 태양 방향·색·환경광을 다시 읽는다 |
| 청크 메시를 새로 뜨었을 때 | 지형 청크는 `material_override` 로 재질을 쓴다 — 그쪽도 덮개를 받는다 |
| 청크 키트를 새로 깔았을 때 | 부품은 표면 덮개다. 모듈이 이미 덮은 면은 건너뛴다 |

- **덮는 것**: 키트 부품(표면 덮개), 지형 청크(`material_override`).
- **안 덮는 것 — 일부러**: `_material()` 이 거는 **발광**(사이트 표식·유닛·바닥판)과 **알파**(영웅 흐림). 툰 셰이더에 그 두 항이 없어서 덮으면 표식의 빛과 흐림이 사라진다. 재질 덮개가 있는데 그게 발광·투명이면 **표면도 안 덮는다** — 어차피 안 보이기 때문이다.
- **트리 밖 뷰 가드**: 단위 테스트는 뷰를 트리에 안 넣고 만든다. 그때 `global_transform` 을 읽으면 엔진 경고가 시험마다 찍힌다 — 지역 변환으로 대신한다.
- **필드 확인**: `godot --path godot -s tools/shot_3d.gd` → `screenshots/explore_3d.png`. 지형 능선에 밴드가 보이고 프롭 색은 A 대역이다. 노출 0.70 에서 카메라를 등진 프롭이 거의 검었서 0.63·2.6 으로 다시 맞췄다(§3.9 표).
- **계약 검사**: `tests/unit/test_toon_shade.gd` 7건(덮기·되돌리기·값 반영·재질 덮개·발광/알파 제외), `test_view_3d.gd` 54건 통과.

## 4. 아직 못 한 것

- **C 를 채택했다** (§3.10) — `view_3d` 가 키트·지형 청크를 툰으로 덮는다. 발광(사이트 표식·유닛)과 알파(영웅 흐림)를 쓰는 재질은 표준 그대로 둔다.
- **ruins 바이옴이 아직 16% 밝다** — 환경광 배율을 바이옴별로 나누는 작업이 남았다(§3.9 표).
- **A 자체가 지금 움직인다** — 같은 노출·광택에서 두 번 재었는데 A 의 ruins 평균이 0.274 → 0.286 으로 바뀌었다(다른 작업이 시각 팔레트·뷰를 같이 고치는 중). 후보를 고를 때는 **한 실행 안에서** A 와 C 를 나란히 재야 한다 — 하네스는 그렇게 만든다.
- **26바이옴 전체로는 안 뽑았다.** 견본대는 자연 표면·도시 폐허 둘뿐이다. 나머지 키트 7종은 같은 하네스에 `BIOMES` 를 늘리면 된다.
- **캐릭터·지형까지 C 를 덮은 판정은 없다.** 시트의 C 는 부품에만 셰이더를 걸었다(후보 정의는 "전 재질").
- **회전 기준축은 잠겼다** (2026-10-26) — 무너진 아치의 상인방이 뒤(`-Z`)로 빠져 있고, 생성기 `axis_check()` 와 GUT 테스트가 그 부호를 지킨다 (무게중심 z 실측 −0.52). 위 후보 둘과는 독립이라 이 결정이 먼저 서도 문제가 없다.
