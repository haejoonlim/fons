# 아트 스타일 리서치 — 로우폴리 3D 키트 (2026-10-26)

[바이옴_에셋_계획](../design/바이옴_에셋_계획.md) §7 의 **스타일 슬롯**을 채우려고 외부 자료를 읽은 기록이다.
이 문서는 **참고자료**지 정본이 아니다 — 채택한 값은 [ART_BIBLE](ART_BIBLE.md) 의 "확정" 절에 적고, 데이터로 옮길 때는 `tools/tracked_numbers.json` 을 먼저 고친다 (AGENTS §1·§4).

읽은 것: 배포 에셋 팩의 제품 페이지와 엔진 공식 문서. 페이지가 값을 밝히지 않은 항목은 **확인 못 함**으로 적었다. 추정으로 메우지 않았다.

## 0. 슬롯별 판정

| 계획 §7 의 슬롯 | 이 조사가 준 것 | 판정 |
|---|---|---|
| 회전 기준축 (§9 미결정) | glTF 2.0 정면 `+Z` · Godot 에셋 정면 `+Z` | **닫힘** — 생성기가 `+Z` 로 굽고 뷰는 yaw 만 돌린다 |
| 폴리곤 예산 | 배포 팩 4종의 tris 공개 실태 + LMHPOLY 실측 범위 | **부분** — 상한을 올릴 근거 없음, 파일럿 값 유지 |
| 텍스처 해상도·팔레트 텍스처 | KayKit 실측 1건 (1024×1024 그라디언트 아틀라스) | **부분** — 정점색 경로를 바꿀 근거 없음 |
| 셰이딩 (플랫·스무스·툰) | 공개 사례 3건 모두 미기재 | **확인 못 함** — 지금 값 유지 |
| 아웃라인 | 제품 페이지에 기본 아웃라인 명시 사례 없음 | **없음 유지** |
| 모듈 격자·조각 수 | Godot 1유닛=1m · 정수배 관행 · 공통 조각 수는 없음 | **부분** — 5유닛 격자 유지 |
| 프롭 배치 규칙 | Unreal foliage 의 경사·고도·노멀·겹침·배제 구역 | **입력** — P3 경사 마스크의 근거 |

## 1. 폴리곤 예산

배포 팩 가운데 **개별 메시의 삼각형 수를 페이지에 밝힌 사례는 넷 중 하나뿐**이었다.

| 팩 | 페이지에 적힌 값 |
|---|---|
| [LMHPOLY Low Poly Nature Bundle](https://www.lmhpoly.com/game-assets/low-poly-nature-bundle) | 바위 8~400 · 나무·목재 20~919 · 식생 4~373 · 지형 2~12,090 tris |
| [Quaternius Stylized Nature MegaKit](https://quaternius.itch.io/stylized-nature-megakit) | 모델 116개 (나무 40 · 식물·꽃 35 · 바위 27) — **tris 미기재** |
| [KayKit Forest Nature Pack](https://kaylousberg.itch.io/kaykit-forest) | 구성과 모델 수만 — **tris 미기재** |
| [Kenney Nature Kit](https://kenney.nl/assets/nature-kit) | 파일 330개 — **tris 미기재** |
| [Synty POLYGON Nature](https://assetstore.unity.com/packages/3d/vegetation/trees/polygon-nature-pack-art-by-synty-120152) | **tris 미기재** |

- 지형 범위가 2~12,090 으로 넓어 **바닥 타일·높이 조각·랜드마크를 한 예산으로 묶을 근거가 없다.** 그 페이지도 셋을 나눠 적지 않는다.
- 우리 파일럿 실측(합 650 tris · 나무 178 · 바위 98 · 둔덕 80 · 프롭 21~105 · 바닥 2)은 확인된 나무 20~919 · 바위 8~400 **안쪽**이다 (자체 실측).
- 그래서 이번 조사가 바꾸는 것은 없다 — 상한을 새로 정할 근거가 나오지 않았다. 이 범위를 넘는 부품이 생기면 그때 이 표와 대조한다.

## 2. 텍스처·머티리얼

| 팩 | 방식 |
|---|---|
| KayKit Forest | 단일 그라디언트 아틀라스 **1024×1024**, 최적화용 **128×128** 다운샘플 안내 |
| Quaternius Stylized Nature | 텍스처 처리 명시 — 아틀라스 여부·해상도 **확인 못 함** |
| Kenney Nature Kit · Synty POLYGON Nature | 텍스처 유무·해상도 **확인 못 함** |

- Synty FAQ 의 4K 목표는 **인터페이스/UI 팩 문맥**이라 3D 텍스처 해상도 근거로 쓸 수 없다.
- 우리 키트는 텍스처가 0장이다 — 색은 전부 `climate.ambient`·`category` 에서 파생한 정점색·머티리얼 색이다 (계획 §4). 아틀라스를 넣으면 바이옴 색이 이미지에 구워져 **수치를 바꿀 때 그림이 따라오지 않는다.** 이 판단을 뒤집을 근거는 나오지 않았다.

## 3. 셰이딩·아웃라인

- Quaternius 는 Source 버전에 스타일라이즈드 셰이더(잔디 바람·나뭇잎)를 포함한다고 적는다. KayKit 은 잔디·정점 셰이더용 **unshaded base** 를 따로 제공한다. 이 둘은 셰이딩 모드가 아니라 제공 파일의 차이다.
- 어느 팩도 **플랫·스무스·툰을 명시하지 않는다** → 확인 못 함.
- 기본 아웃라인을 내장했다고 밝힌 제품 페이지도 없다. "없다"가 아니라 **페이지에서 확인 못 했다**는 뜻이다.
- 지금 구현은 지형 법선을 높이 함수의 중심차분으로 내고, 키트 부품은 구운 법선을 쓴다. 이번 조사로 바뀌는 값은 없다.

## 4. 모듈 격자·조각 구성·심

- [Godot 3D 소개](https://docs.godotengine.org/en/stable/tutorials/3d/introduction_to_3d.html): **1 유닛 = 1 m**, 뷰포트 그리드 기본 **1 m**. [Unreal 스냅](https://dev.epicgames.com/documentation/unreal-engine/actor-snapping-in-unreal-engine?lang=en-US)은 스냅 증분을 사용자가 바꾼다.
- 레벨 디자인 관행은 **플레이어와 공간을 먼저 정하고, 모듈 치수를 기준 그리드의 정수배로 맞추는 것**이다 ([Level Design Book — Metrics](https://book.leveldesignbook.com/process/blockout/metrics) · [Modular kit design](https://book.leveldesignbook.com/process/blockout/metrics/modular) · [Game Developer — Creating Modular Game Art](https://www.gamedeveloper.com/production/creating-modular-game-art-for-fast-level-design)).
- 1·2·4·5m 중 무엇이 보편적인지, **3D 키트가 몇 조각으로 구성되는지는 확인 못 함.** 실무 분류안은 바닥 / 직선 경계 / 모서리 / 높이 변화 / 접합·종단 다섯이다.
- 심 처리: 독립 모듈은 **용접이 필수가 아니다.** 경계 위치·높이·법선·재질이 맞으면 조립된다. [Unreal Landscape](https://dev.epicgames.com/documentation/unreal-engine/landscape-technical-guide-in-unreal-engine?lang=en-US) 는 이웃 컴포넌트의 경계 정점 행을 **중복 저장**한다. 한 메시로 합칠 때만 [Blender Merge by Distance](https://docs.blender.org/manual/en/latest/modeling/meshes/editing/mesh/merge.html) 로 경계를 용접한다.
- 우리는 청크 경계를 단일 높이필드로 없앴다(`FonsTerrain.height_at`). 위 관행과 같은 방향이므로 격자와 조각 규칙은 그대로 둔다.

## 5. 회전 기준축 — §9 미결정 하나를 닫는다

| 형식 | 위 축 | 정면 |
|---|---|---|
| [glTF 2.0](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html) | `+Y` | **`+Z`** |
| [Godot 에셋 규약](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/model_export_considerations.html) | `+Y` | **`+Z`** (카메라·기본 노드 전방은 `-Z`) |
| Unity | `+Y` | `+Z` |
| Unreal | `+Z` | `+X` |

- 우리는 `.glb`(glTF)를 쓰므로 **정면 `+Z` 하나로 끝난다.** 키트 생성기가 그 축으로 굽고, 뷰는 yaw 만 돌린다.
- §9 는 비대칭 모듈이 들어오는 S3 에서 확정하자고 적었다. 이 값이면 S3 에서 **비대칭 부품 하나를 돌려 앞뒤가 구분되는지**를 테스트로 잠그면 된다.

## 6. 프롭 배치 규칙

[Unreal Foliage](https://dev.epicgames.com/documentation/unreal-engine/open-world-tools-property-reference-in-unreal-engine) 는 배치 제한을 다섯 축으로 둔다 — 경사각 · 고도 · 지형 레이어 · 표면 노멀 정렬 · 월드 충돌. [Procedural Foliage](https://dev.epicgames.com/documentation/unreal-engine/procedural-foliage-tool-in-unreal-engine?lang=en-US) 는 **인스턴스 반경**으로 겹침을 판정하고 **Blocking Volume** 으로 배제 구역을 만든다.

우리 배치는 지금 5유닛 칸 시드 고정과 조우 지점 회피뿐이고, 경사 마스크는 P3 대기다. 위 다섯 축을 그대로 옮길 필요는 없지만, P3 에서 **경사 · 겹침 · 배제 구역**을 따로 두는 편이 낫다는 근거는 된다.

## 7. 이 조사가 닫지 않은 것

- **셰이딩 방식**(플랫·스무스·툰) — 배포 팩 페이지에 없다. 스타일 결정은 사람이 한다.
- **텍스처 유무** — 정점색 경로를 유지하는 한 정할 필요가 없다.
- **모듈 조각 수와 그리드 크기** — 업계 공통값이 확인되지 않았다. 우리 5유닛과 파일럿 조각 수는 필드 40×28 에서 나온 값이다.
- **원본 팩의 라이선스** — 이 조사 범위가 아니다. 외부 에셋을 조달하면 [godot/assets/CREDITS.md](../../godot/assets/CREDITS.md) 규칙을 따른다 (계획 §6).
