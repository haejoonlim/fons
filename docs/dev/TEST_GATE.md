# 테스트 게이트 — 거짓 통과 방지 3종

Godot 테스트는 `./tools/test_godot.sh` 하나로만 돌린다. 이 스크립트는 **"테스트가 실제로 돌았고, 그 결과가 지금 코드의 것"** 일 때만 초록을 낸다. 아래 세 장치는 모두 실제로 초록이 거짓이었던 사건 뒤에 들어갔다.

```
./tools/test_godot.sh                          # Godot 단독 (임포트 → GUT → 판정)
./.venv/bin/python tools/gate_all.py --godot   # 문서·데이터·시뮬 + Godot 전수
```

## 계약

마지막 줄은 `[PASS] godot` 또는 `[FAIL] godot — 이유`이고, 종료코드는 0 아니면 1이다. `tools/gate_all.py` 는 그 한 줄만 읽어 단계 성패를 판정한다(`tools/gate_contract.py` G-1·G-2). 그래서 앞쪽에 사람용 출력이 무엇을 찍든 상관없다.

## 방지 1 — 테스트를 0건 돌리고 exit 0

**사건**: `godot --headless -s addons/gut/gut_cmdln.gd -gexit` 를 단독으로 돌리면, `.godot` 임포트 캐시가 없는 새 사본에서 GUT 클래스가 임포트되지 않은 채 **한 건도 실행하지 않고 exit 0** 을 반환한다 (2026-10-16, `docs/dev/DEV_PLAN.md` 부록 A #10).

**장치**: 스크립트가 `godot --headless --import` 를 먼저 돌리고, GUT 뒤에 junit 결과 파일 존재와 `tests` 속성을 확인한다. 파일이 없거나 `tests="0"` 이면 실패.

**금지**: GUT 단독 실행. 임포트를 건너뛰는 순간 위 사건이 그대로 재현된다.

## 방지 2 — 실행되지 않은 테스트 스크립트

**사건**: `tests/unit/test_encounter.gd` 가 없는 클래스(`FonsEncounter`)를 참조해 파싱에 실패했는데, GUT 는 그 파일을 **조용히 건너뛰고** 나머지 35건을 전부 통과로 보고했다. 새 테스트를 쓰고도 안 돌아간 것을 알 수 없었다 (2026-10-18 실측).

**장치**: junit 의 `testsuite name="…"` 집합과 디스크의 `tests/**/test_*.gd` 집합을 비교한다. 디스크에만 있는 파일이 하나라도 있으면 그 목록을 찍고 실패.

**실측 예**: 2026-10-25 21:57 실행에서 `Scripts 34 · Tests 392 · All tests passed` 가 나왔지만, 디스크에는 38개가 있었다. 누락 4건(`test_day.gd`·`test_estate.gd`·`test_island_clock.gd`·`test_main.gd`)을 지목해 `[FAIL] godot — 테스트 스크립트 누락` 으로 끝났다 (자체 실측). 다른 작업자가 그 무렵 테스트 파일을 저장하는 중이었다.

## 방지 3 — 편집 중에 돌린 실행

**사건**: 같은 코드·같은 에셋인데 실행마다 답이 달라졌다. 테스트 수가 451 → 465 → 471 → 475 → 484 → 486 으로 늘었고, 실패 파일도 `test_estate.gd` 8건 → `test_main.gd` 7건 → 0건으로 갈아탔다 (2026-10-25 자체 실측). 파일 수정 시각을 대조하니 내 실행과 다른 작업자의 편집이 겹쳐 있었다.

**장치**: 실행 직전에 `mktemp` 로 시각을 찍고, GUT 가 끝난 뒤 그 시각 이후에 바뀐 소스를 찾는다. 검사 대상은 `*.gd` `*.tscn` `*.tres` `*.json` `project.godot` 이고, `.godot/`(임포트 캐시)는 Godot 이 스스로 만지므로 제외한다. 하나라도 있으면 바뀐 파일 목록과 함께 `[FAIL] godot — 실행 중 소스 변경 (편집 중 실행)`.

**왜 실패로 처리하나**: 그 실행은 이후 편집을 반영하지 않은 결과다. 초록이어도 다음 코드의 근거가 못 되고, 빨강이면 이미 고쳐진 실패를 쫓게 된다. 어느 쪽이든 판정으로 쓸 수 없으니 초록을 내지 않는다.

**한계**: 파일 **삭제**는 잡지 못한다(`find -newer` 는 생성·수정만 본다). 삭제가 끼면 방지 2가 스크립트 누락으로 잡거나, 다음 실행에서 정상 복구된다.

## 언제 무엇이 잡히나

| 상황 | 잡는 장치 | 결과 |
|---|---|---|
| 임포트 캐시 없이 GUT 단독 실행 | 방지 1 | junit 없음 → 실패 |
| 테스트가 0건 실행됨 | 방지 1 | `tests="0"` → 실패 |
| 테스트 파일이 파싱 실패로 건너뛰어짐 | 방지 2 | 누락 스크립트 목록 → 실패 |
| 실행 중 다른 사람·에이전트가 소스를 저장 | 방지 3 | 바뀐 파일 목록 → 실패 |
| 테스트가 진짜로 실패 | GUT 종료코드 | `GUT 실패 (exit=N)` |

## 실패 메시지별로 할 일

- `GUT 결과 파일 없음` — `--import` 단계가 실패했다. 그 위 로그의 첫 에러를 본다.
- `테스트 스크립트 누락 (실행 안 됨)` — 지목된 파일이 컴파일되지 않는다. 클래스 이름 오타나 사라진 `class_name` 을 확인한다.
- `실행 중 소스 변경 (편집 중 실행)` — 편집을 멈추고 다시 돌린다. 동시에 도는 작업이 있으면 끝날 때까지 기다린다.
- `GUT 실패 (exit=N) · 테스트 M건` — 진짜 실패다. stderr 의 실패 목록을 본다.

## 함정

`godot --headless --check-only -s tests/unit/foo.gd` 로 파일 하나만 컴파일해 보는 방법은 **autoload 를 해석하지 못한다.** `DataLoader` 같은 autoload 이름을 쓰는 파일은 GUT 에서 멀쩡히 통과하는데도 `Identifier not found: DataLoader` 로 실패한다 (2026-10-25 자체 실측). 파싱 여부는 GUT 실행 결과로만 판단한다.
