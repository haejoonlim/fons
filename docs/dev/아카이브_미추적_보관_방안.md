# 아카이브 미추적 37개 — tar 밖으로 꺼내는 방안

[아카이브_복원_체크리스트.md](아카이브_복원_체크리스트.md) §9 는 tar 를 잃으면 115개를 잃는다고 적는다. 그중 37개가 **미추적 작업 파일**이다. 이 문서는 그 37개가 무엇인지, 왜 아무렇게나 버릴 수 없는지, 어떻게 `.git` 안으로 옮기는지를 정한다.

기준 스냅샷은 2026-10-24 아카이브(`soul-commander-archive-2026-10-24`)다. 이 머신의 `~/soul-commander` 에는 클론이 없다(자체 실측 · 2026-10-25).

## 1. 무엇이 있나 — 37개 · 779,235B

| 정책 실험 | 6 | `policy_export_gate.py` · `measure_bias_sensitivity.py` | `train_neural_policy.py` 가 관문을 부른다 (자체 실측) |

## 2. 왜 급한가 — "잡동사니 37개"가 아니다

`.git` 만으로 세운 트리는 파일 수가 맞아도 **게이트를 돌릴 수 없고 Unity 가 컴파일되지 않는다.**

- `gate_all.py` 는 미추적 검사 20개를 `sys.executable` 로 실행한다. 없으면 그 단계가 실패한다.
- `DecisionFusion.cs` 와 `DecisionFusionTests.cs` 가 `TeacherGateTelemetry` 를 부른다. 클래스가 없으면 컴파일 오류다.
- `check_editmode_coverage.py` 는 `editmode_map.json` 없이는 baseline 을 못 읽는다.
- `train_neural_policy.py` 는 export 관문으로 `policy_export_gate.py` 를 부른다.

즉 지금의 `.git` 은 "복원된 저장소"가 아니라 **검사 불능 트리**다. 20개 검사는 문서(`design-docs/_tools/README.md` · GDD 99)에 이미 등재돼 있어, 없는 쪽이 오히려 기록과 어긋난다 (자체 실측).

## 3. 선택지

| 안 | 하는 일 | 장점 | 한계 |
|---|---|---|---|
| A. 본 이력에 편입 | 32개를 `main` 에 커밋, 생성물 5개는 ignore | 새 클론이 바로 게이트를 돌린다 | `~/soul-commander` 에 클론이 없어 지금은 불가(자체 실측). 아카이브 `main` 을 고치면 복원 기준(HEAD `669f0be`)이 흔들린다 |
| B. 독립 bundle | 37개만 담은 루트 커밋을 bundle 로 만든다 | 265KB. tar 도 `.git` 도 없이 `git clone` 으로 37개가 나온다. 아카이브 불변 | 원래 이력과 이어지지 않는다. 37개만 담는다 |
| C. 이력 전체 bundle | 252 커밋 + 37개를 한 파일에 | tar 없이 저장소 전체를 세운다 | 약 90MB 중복(자체 실측). `teacher_data`·gitignore 대상은 여전히 빠진다 |
| D. 별도 zip | 37개만 압축 | 가장 단순 | tar 를 잃은 이유(단일 파일)를 그대로 반복한다 |

**권고: B 를 먼저, A 는 살아 있는 클론이 생기면.** B 는 지금 바로 만들 수 있고 아카이브를 건드리지 않는다. C 는 tar 를 은퇴시킬 때만, D 는 원격 복사본을 하나 더 둘 때만 쓴다.

## 4. B 실행 — 4단계 + 도구 1단계

`$A` 는 아카이브, `$S` 는 tar 를 푼 작업 트리, `$R` 은 37개만 담는 새 저장소다. 아카이브 파일과 `.git` 은 건드리지 않는다.

```bash
A=~/Desktop/soul-commander-archive-2026-10-24
S=$(mktemp -d)
R=$(mktemp -d)
tar -xzf "$A"/soul-commander-2026-10-24.tar.gz -C "$S"
cd "$S"
git -c core.quotepath=false status --porcelain | sed -n 's/^?? //p' > "$S/u37.txt"
wc -l < "$S/u37.txt"        # 37
```

1. 37개만 새 저장소에 옮겨 루트 커밋을 만든다. 경로를 그대로 살린다.

```bash
cd "$R"
git init -q
while IFS= read -r f; do
  mkdir -p "$(dirname "$f")"
  cp -p "$S/$f" "$f"
done < "$S/u37.txt"
git add -A
git commit -q -m "archive: tar 에만 있던 미추적 37개 (2026-10-25)"
git branch -M main
git ls-tree -r --name-only HEAD | wc -l    # 37
```

2. 독립 bundle 을 만든다. 부모 커밋이 없으므로 base `.git` 이 없어도 clone 된다.

```bash
git bundle create "$A"/untracked-2026-10-25.bundle HEAD main
git bundle verify "$A"/untracked-2026-10-25.bundle
shasum -a 256 "$A"/untracked-2026-10-25.bundle >> "$A"/sha256.txt
```

기대: 약 265KB(이번 실행 264,841B) · `The bundle records a complete history` (자체 실측 · 2026-10-25).

3. tar 없이 복원되는지 확인한다. 빈 폴더에 clone 하나만 한다.

```bash
T=$(mktemp -d)
git clone -q "$A"/untracked-2026-10-25.bundle "$T"
find "$T" -type f -not -path '*/.git/*' | wc -l    # 37
```

4. 37개가 tar 와 바이트 동일한지 본다. 경로는 NFC 로 맞춘다 — macOS 의 NFD 저장 때문에 정규화 없이 맞대면 같은 파일이 어긋나 보인다.

```bash
python3 - "$A" "$T" "$S/u37.txt" <<'PY'
import hashlib, pathlib, sys, tarfile, unicodedata
A, T, U = (pathlib.Path(p) for p in sys.argv[1:4])
names = [n.strip() for n in open(U, encoding="utf-8") if n.strip()]
want = {unicodedata.normalize("NFC", n) for n in names}
got = {}
with tarfile.open(A / "soul-commander-2026-10-24.tar.gz", "r:gz") as t:
    for m in t:
        rel = m.name[2:] if m.name.startswith("./") else m.name
        rel = unicodedata.normalize("NFC", rel)
        if rel in want and m.isfile():
            got[rel] = hashlib.sha256(t.extractfile(m).read()).hexdigest()
diff = [n for n in names if hashlib.sha256((T / n).read_bytes()).hexdigest()
        != got.get(unicodedata.normalize("NFC", n))]
print("tar 에서 찾은 수:", len(got))
print("바이트 불일치:", len(diff))
PY
```

기대: `37` · `0` (자체 실측 · 2026-10-25).

5. 체크리스트 도구에 10단계를 더한다. 9단계는 그대로 둔다 — 그 단계는 HEAD+patch 로 세운 트리의 손실 115를 재는 검사라 여전히 참이다. 새 단계는 아카이브와 무관하게 bundle 만 clone 해서 **37개**와 37개 바이트 불일치 **0** 을 본다(자체 실측 · 2026-10-25). 이 검사가 통과하면 tar 가 사라져도 37개는 남는다.

## 5. A 로 넘어갈 때 — 커밋 3개

살아 있는 클론이 생기면 bundle 을 clone 해 32개만 골라 셋으로 나눈다. 생성물 5개는 bundle 안에만 두고 `main` 으로 가져오지 않는다. 나눠야 되돌리기 쉽다.

1. 게이트 검사 20개 + `editmode_map.json` — `gate_all.py` 가 부르는 단위.
2. `TeacherGateTelemetry.cs`(+meta) + 정책 스크립트 6개 — AI 코드와 실험.
3. 문서 2개 + `.ignore` — 문면과 검색 설정.

생성물 5개는 `main` 에 넣지 않고 `.gitignore` 에 적는다.

```gitignore
design-docs/_tools/bias_sensitivity_report*.json
design-docs/_tools/mitigation_report.json
design-docs/_tools/parity_report.json
design-docs/_tools/policy_sensitivity_report.json
```

각 커밋 뒤 `python3 design-docs/_tools/gate_all.py --unity=skip` 을 돌린다. `check_cs.py` 단계가 Unity 배치 없이 C# 컴파일을 본다. EditMode 테스트(`tools/run_editmode_tests.sh`)는 이 머신에서 돌릴 수 없다 — 이 기기의 macOS 가 Unity 최소 요구 버전보다 낮다. 게이트 검사가 저장소 안으로 들어오는 커밋이니, 그 전후로 게이트가 같은 초록인지 보는 것이 이 작업의 검증이다.

## 6. 하지 않는 것

- 아카이브 `main` 이나 HEAD `669f0be` 를 고치지 않는다. 복원 기준이 흔들린다.
- tar 의 미커밋 수정 44건·삭제 22건을 37개 bundle 에 섞지 않는다. 그건 `uncommitted-restore.patch` 몫이다.
- 생성물 5개를 `main` 에 넣지 않는다. 다시 만들 수 있는 것이 이력에 쌓이면 diff 만 늘어난다.
- LFS 착시 7건을 `git add` 하지 않는다.

## 7. 남는 위험

- 이 방안은 **bundle 파일이 살아남는 경우**에만 37개를 구제한다. tar 와 같은 폴더에만 두면 폴더째 사라질 때 함께 사라진다 — 다른 디스크나 원격에 한 부 더 둔다. 이력 전체가 필요하면 C(약 90MB)를 쓴다.
- `teacher_data` 67MB, `.gitignore` 대상 3개, `__pycache__` 74개는 이 방안의 대상이 아니다. 앞의 둘은 별도 판단이 필요하고, pyc 는 버려도 된다.
- `TeacherGateTelemetry.cs` 가 `main` 에 들어가기 전까지, `.git` 으로 세운 트리는 여전히 컴파일되지 않는다. 37개 bundle 은 "잃지 않기"까지고, "바로 쓸 수 있게"는 A 의 몫이다.
