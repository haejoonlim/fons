## 3. 선택지

### A. 아카이브 후 삭제 (권장)

한 개의 tar 로 묶어 두고 클론 폴더를 지운다. 381MB → 약 200~250MB(압축률에 따라), 작업 폴더는 0MB.

```bash
# 1) 이력 + 미커밋 변경 + 미추적 게이트를 한 번에 보존
cd ~/soul-commander
git diff > /tmp/soul-commander-uncommitted.patch
tar --exclude='./.venv' --exclude='./graft' --exclude='./web/hero_viewer' \
    -czf ~/Desktop/soul-commander-archive-2026-10-24.tar.gz .
# 2) 열리는지 확인 (지우기 전에 반드시)
tar -tzf ~/Desktop/soul-commander-archive-2026-10-24.tar.gz | wc -l
# 3) 확인 뒤에만
rm -rf ~/soul-commander
```

`.venv`(72MB, 재설치 가능)와 `graft`(29MB, 인덱스 캐시)는 뺀다. `teacher_data`·`.git`·`web` 은 **넣는다**.

- 얻는 것: 지금 작업 폴더에서 381MB 회수, 원본 이력·교사 데이터는 파일 하나로 보존
- 잃는 것: 클론을 바로 grep 할 수 없음(필요하면 tar 풀기). 폰즈 게이트는 이 클론을 안 본다
- 위험: 낮음. 단, tar 검증(`-tzf`) 전에 `rm` 하지 않는다

### B. 읽기 전용으로 남긴다

`chmod -R a-w` 로 잠그고 참고용으로 둔다. 정본 대조가 필요할 때 바로 열 수 있다.

- 얻는 것: 즉시 대조 가능, 위험 0
- 잃는 것: 381MB 계속 점유, 미커밋 80건이 그대로 방치되어 "어느 쪽이 최신인지" 혼동이 남는다

### C. 그냥 삭제

**지금은 권하지 않는다.** 원격이 없어 `.git` 252커밋과 `teacher_data` 67MB 가 함께 사라진다. 폰즈는 코드를 다시 만드는 저장소라 원본 이력을 대신하지 못한다. 정말 지우려면 A의 1~2단계(tar + 검증)만 먼저 하고 3단계를 실행한다.

## 4. 결정하면 같이 정리할 것

- **미커밋 37건**은 A를 고르면 patch 로만 남는다. 원래 `uncommitted.patch` 는 이진 hunk 가 잘려 `git apply` 가 거부하므로, 적용되는 `uncommitted-restore.patch` 를 따로 넣었다(§5). 그중 다시 쓸 만한 것은 `check_cs.py`·`check_selftest_teeth.py`·`check_sim_smoke.py` 의 보강분이다 — 폰즈 게이트에 해당 검사가 없으므로 옮길 가치가 있다. 미이관 검사 79종을 꺼내 판정한 표는 [원본게이트_이관_목록.md](원본게이트_이관_목록.md).
- **`LiberationSans.ttf` 는 350,200B 그대로다 (자체 실측).** 앞선 세션에 이 파일을 '350,200B → 131B 로 바뀌어 있다'고 적었는데 착시다. `unity/.gitattributes` 가 `*.ttf` 를 `filter=lfs` 로 잡는데 이 파일은 LFS 포인터가 아니라 원본으로 커밋돼 있어, git 이 작업 트리를 읽을 때만 130여 바이트 포인터로 바꿔 본다. `git hash-object --no-filters` 로 재면 index·HEAD·디스크 해시가 모두 같다. 같은 이유로 `*.png` 5개도 늘 수정으로 보인다(§5).
- **원격을 되살릴 생각이면** A보다 먼저 해야 한다. 되살린 뒤 push 하면 이력이 GitHub 에도 생겨 A의 위험이 더 줄어든다.

표의 마지막 두 줄은 원본 저장소 없이 되풀이할 수 있다. `tar -xzf` 로 풀고 그 안 `.git` 으로 `git status` 를 돌리면 같은 수가 나온다. 경로를 맞댈 때는 정규화가 필요하다 — macOS 는 NFD 로 주고 git 은 `core.precomposeunicode` 로 NFC 로 돌려준다.

`1,652개 sha256` 줄만은 되풀이할 수 없다. 그 대조를 뜬 뒤 원본 폴더를 지웠고, `listing.txt` 에는 경로 1,789줄만 있어 크기·해시 열이 없다(tar 항목 목록과 `diff` 0 — tar 사본이라 새 정보가 없다). 그 자리를 메우려고 넣은 것이 `HEAD` blob 대조다. 추적 1,523개 중 1,464개가 바이트 동일이고, 남는 59개는 수정 37 · 삭제 22 다.

`수정 37` 은 필터를 끄고 잰 값이다. `git status` 는 44 로 센다 — 차이 7개는 실제 변경이 아니라 `unity/.gitattributes` 의 `filter=lfs` 가 만든 착시다(자체 실측 · 2026-10-24). `Icon.png`·`Logo.png`·`Skin/Sheet1~3_*.png`·`NanumGothic.ttf`·`LiberationSans.ttf` 가 LFS 포인터가 아니라 원본 바이너리로 커밋돼 있어서, tar 를 새로 풀면 git 이 늘 수정으로 본다. `git archive` 도 같은 7개를 두고 `should have been pointers, but weren't` 로 경고한다. `git hash-object --no-filters` 로 재면 index·HEAD·디스크 해시가 셋 다 같다.

**정정.** 2026-10-24 1차 대조에서 `Icon.png`·`Logo.png` 를 "`HEAD` 와 내용이 다른데 patch 에는 없다"고 적었다. 틀렸다 — 둘 다 `HEAD` 와 바이트 동일하고 복원할 변경분이 없다. 같은 착시로 §4 의 `LiberationSans.ttf` 131B 항목도 함께 정정했다.

**되살릴 때.** 이 7개는 그대로 두는 편이 낫다. `git lfs migrate import` 는 252커밋을 다시 쓰고 `HEAD` 해시(`669f0be`)를 바꾸므로, 기록물로 남긴 아카이브에는 맞지 않는다. 복원한 트리에서 status 만 조용히 시키려면 이 7개를 assume-unchanged 로 표시한다.

```
git update-index --assume-unchanged \
  unity/Assets/Icon.png \
  unity/Assets/Resources/Art/Logo.png \
  unity/Assets/Resources/Art/Skin/Sheet1_Frames.png \
  unity/Assets/Resources/Art/Skin/Sheet2_BarsIcons.png \
  unity/Assets/Resources/Art/Skin/Sheet3_TitleIcons.png \
  unity/Assets/Resources/Fonts/NanumGothic.ttf \
  "unity/Assets/TextMesh Pro/Fonts/LiberationSans.ttf"
```

`unity/Assets` 의 status 줄이 22 → 15 로 줄어든다(자체 실측 · 2026-10-24). 대신 이 7개를 나중에 진짜로 바꿔도 git 이 못 본다 — 읽기용 트리에서만 쓴다. 복원 트리에서 `git add -A` 를 그냥 돌리면 이 7개가 130바이트 LFS 포인터로 커밋된다.

**추가한 것.** `uncommitted.patch` 는 `--binary` 없이 떠서 이진 hunk 가 `Binary files ... differ` 로 잘렸고, `git apply` 가 `cannot apply binary patch ... without full index line` 으로 거부한다. 그래서 tar 판 그대로를 담은 `uncommitted-restore.patch`(594,084B · 38파일 = 수정 37 + 삭제 1)를 옆에 넣었다. `HEAD` 를 풀고 `git apply` 하면 37개가 tar 판과 바이트까지 같아지고 `check_unity_health.sh` 가 지워진다 — 37개 전수 대조로 확인했다(자체 실측 · 2026-10-24). 미추적 37개와 `web/hero_viewer` 삭제 21건은 담지 않았다 — 뒤 21건은 patch 없이 `.git` 에서 꺼낸다.

**꺼내는 법**: `./.venv/bin/python tools/archive_clone.py find <이름>` 로 찾고, `get <경로> [--out 폴더]` 로 꺼낸다. 한글 이름은 tar 명령으로 안 잡히므로(NFD) 이 도구를 쓴다.

전체를 다시 세우는 절차는 [아카이브_복원_체크리스트.md](아카이브_복원_체크리스트.md) 한 장에 있다 — 단계마다 기대 수치를 적었고, 2026-10-24 에 그대로 돌려 27개 항목을 확인했다.

**`web/hero_viewer` 는 작업 트리에서만 빠졌다.** 21개 27.6MiB 가 `HEAD` 에 그대로 있어 `.git` 에서 꺼낼 수 있다. `git --work-tree=<폴더> checkout HEAD -- web/hero_viewer` 로 21개·28,978,232B 를 복원했고 glTF 매직까지 확인했다(자체 실측 · 2026-10-24). 생성 스크립트도 있다 — `design-docs/_tools/headgen/headgen.mjs` 가 three.js 로 `web/hero_viewer/parts` 를 쓴다. 그래도 three.js 판이 달라지면 바이트까지 같은 재생성은 보장되지 않으므로, 원본이 필요하면 `.git` 에서 꺼낸다. tar 크기에서 이 28MB 는 빠지지 않았다(pack 안에 들어 있다). 다만 빠진 작업 트리 사본에 미커밋 수정이 있었는지는 알 수 없다 — `git status` 는 삭제만 기록한다.

**`teacher_data`(`teacher_v1_10k.jsonl`, 70,091,197B)는 tar 작업 트리에만 있다.** `.gitignore` 62행이 디렉터리를 빼서 git 객체에는 없다(`git rev-list --objects --all` 로 teacher_data 0건). 대신 결정론으로 되살린다 — `python3 design-docs/_tools/sim_combat_teacher.py --runs 76 --out <파일>` 이 9초에 같은 파일을 쓰고, sha256 `47ea28969c2cf5f382068a823dc9ff38fc6f8bc1db84b6a8d2769096ac39a6ce` 가 tar 판과 같다(자체 실측 · 2026-10-24). 파일은 10,108줄(133종 × 76런) 전부 JSON 이다.

**손대지 않은 것**: `docs/original/00_읽는법.md` 는 여전히 "없으면 clone 하라"고 적혀 있다. 그 파일은 원본 문면이라 규칙상 고치지 않았고, 대신 [docs/README.md](../README.md) 에 아카이브 위치를 적었다.
