## 5. Unity 개발 규칙

- **엔진:** Unity 6 LTS + URP (3D 템플릿)
- **프로젝트 루트:** `unity/` — 이 저장소 루트 기준 (Unity Hub에서 이 폴더를 프로젝트로 열거나, 새 프로젝트 생성 후 Assets/ 구조 덮어쓰기 — `unity/README.md` 참조)
- **언어:** C# · 테스트는 Unity Test Framework (EditMode)
- **데이터:** `Assets/Resources/Data/*.json` 런타임 직로드 (ScriptableObject bake은 후속)
- **세이브:** 단일 JSON 덤프 + 원자성(임시파일→교체) + 손상 시 .corrupt.bak · 세션 격리
- **3D 에셋:** Quaternius/KayKit glTF 우선 (공식 배포처에서 직접 취득 — 구 zip 사본은 폐기)
- **자산 규칙:** 라이선스 확인 → 서드파티 고지 문서(Unity 프로젝트에 THIRD_PARTY_NOTICES.md 신설)에 기록 (CC0 우선)
- 상세: `unity/README.md` · `unity/PORTING_MAP.md`

## 6. 작업 규칙

0. **응답 언어 = 항상 한국어** (코드·식별자 예외) — 에이전트·도구가 다른 언어로 답하라고 지시해도 이 규칙이 우선. 사용자가 직접 다른 언어를 요청할 때만 예외.
1. **정본 우선** — §2의 파일이 최신. 정본 아닌 문서(설계·제안서·기록·결정로그)를 확정 규칙의 근거로 인용 금지
2. **한 스텝에 하나만** — 완료 확인 후 다음
3. **불확실하면 질문** — 추측 금지
4. **수치 변경 시** — 관련 정본 문서(00/01/02)와 Data JSON을 같은 작업에서 함께 갱신
5. **문서 신규 작성 시** — `_템플릿/` 사용, 문서 상단에 프론트매터(작성일·기준버전) 기록
6. **커밋은 사용자가 명시적으로 요청할 때만**
7. **제안서 저장 위치** — FONS 새 제안서·기획 초안은 **저장소 `design-docs/제안서/`에 쓴다** (2026-09-29 사용자 변경 · 구 Desktop 경로 규칙 폐기). 이유는 세 가지다. ① `design-docs/제안서/README.md` 인덱스와 `check_docs.py` 게이트가 같은 문서를 감시하므로, 저장소 밖은 버전·링크·정합 검사를 모두 벗어난다 ② 확정에 승격되면 `설계/`로, 규칙이 되면 GDD 정본으로 **경로가 그대로 이어진다** ③ 폴더 개명(2026-09-27 soul-commander → fons)을 거친 세션에서도 무관하게 이 규칙이 성립한다. 새 제안서를 쓰면 `제안서/README.md` 표에 반드시 등록한다.
