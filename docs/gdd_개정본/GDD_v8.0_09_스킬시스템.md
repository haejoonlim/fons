## 1. 목적 & 범위

- **목적**: 영웅이 **해온 일**이 그대로 성장이 되는 시스템 — AI가 행동을 반복하면 커맨드(스킬)로 각인되고, 스킬 축적이 전직 방향을 결정 (인과 순서: 기존 "전직→스킬"의 역전)
- **범위 (in)**: 행동 태그 체계 · 영웅 유틸리티 AI (P0) · 스킬 발견/단계 성장/융합 · 스킬 이름 자동생성 · 전직 클러스터 게이트 v2 (제안) · 개발 로드맵
- **비범위 (out)**: 전투 데미지 공식 (01) · 소환 롤 (05) · 생활 시설 경제 (04) · 스킬 UI 상세 (구현 세션)

## 4. P0 — 영웅 유틸리티 AI 스펙 (구현 최우선 · v0.2 다양성 강화)

### 4-1. 행동 스코어 공식

```
Score(a) = B(a) × S(a) × M(P, a) × A(apt, a) × K(skills, a) × C(context) × R(routine) + ε
```

| 항 | 내용 | 가안 |
|---|---|---|
| B(a) | 태그 기본 가중 | 도메인 기본 1.0 · 영웅 역할 태그와 일치 시 ×1.2 |
| S(a) | 스탯 요인 | 행동 관련 스탯 ÷ 파티 평균 (공격=ATK/MAG · 방어=DEF · 치유=MAG) |
| M(P, a) | **성격 벡터 매핑** — 메인 성향 13종을 5축 벡터로 환산 + 부가 성격 2종 미세 보정 (§4-4) | 0.7~1.3 × (1+Σ부가 ±3~5%) · PERS_VECTOR·PERS_ACTION_W (P0 확정) |
| A(apt, a) | 적성 효율 배율 — **hero['적성_효율'] 직접 참조** (v0.8 구현 명세 하단) | `적성_효율[행동 태그의 적성]` 값 그대로 곱함 — 티어(1.00~2.30) × 부가 가중(선호 ×1.10 · 반대 ×0.95 · 도메인당 1회 캡)이 이미 합산된 필드 (gacha_test make_hero 실측 · CP 무영향) |
| K(skills, a) | 보유 스킬 선호 | 1 + 0.05 × 관련 스킬 단계 합 (자기강화 루프) |
| C(context) | 상황 계수 | 아군 부상 → 치유 ×2 · 적 다수 → 광역 ×1.5 · 자기 저체력 → 후퇴 ×2 등 (문맥 13종 연동) |
| R(routine) | **습관(루틴) 항 — v0.2 신설** | 최근 반복 패턴 가중 (직전 N행동 중 같은 태그 비중 × 0.9~1.15) — "습관이 된다" 체감 · 개체별 루틴 분화 |
| ε | 개체 성격 시드 노이즈 | ±10% — **개체별 고유 노이즈 패턴** (결정론 시드 — 동일 상황이면 같은 개체는 같은 성향으로 행동) |

- **판정 주기**: 전투 = 0.5초 틱마다 최고점 행동 / 영지 = 현재 행동 완료 시 재판정
- **CP 무영향**: M·R은 행동 선호일 뿐 스탯·CP 재계산에 미반영 (CP는 05 §7 그대로)

#### 4-1-1. A항(적성 효율) 구현 명세 — hero['적성_효율'] 연결 (v0.8)

> gacha_test `make_hero`가 이미 생성하는 `적성_효율` 필드를 P0 AI가 **그대로 소비**하는 규격 — 계산 이원화 금지 원칙 (AI가 효율을 다시 계산하지 않음).

| 항목 | 규격 |
|---|---|
| 필드 | `hero['적성_효율'][적성명] = APT_TIER[티어] × 부가가중` — 10 공통 적성 전부 (희귀 적성은 부가 가중 대상 아님 → 티어 값만) |
| 부가가중 | 선호 도메인 ×1.10 · 반대 성향 도메인 ×0.95 · **도메인당 1회 캡** (v0.8 — 부가 2종이 같은 도메인 선호해도 중복 없음) |
| A항 매핑 | 행동 a의 태그 → 적성 매핑표 `ACTION_APT` (P0 상수): 채집·벌목·농부·광부·목수·대장·조제·요리·간호·연구 — 태그와 동명 적성 1:1 · **전투 도메인 태그는 A항 1.0 고정** (적성=생활 전용 — 05 §6 체계 유지) |
| 소비 예 | `A = hero['적성_효율'].get(ACTION_APT.get(a_tag, ''), 1.0)` — 매핑 없는 행동은 1.0 (전투 행동 전부 여기 해당) |
| 실측 범위 | ×0.95(반대×티어1) ~ ×2.53(선호×명장 2.30) — 시뮬 n=20,000 확인 |
| 불변식 | ① CP·스탯·등급 무영향 (동적 증명: SUB_EFF_X를 9.99로 극단 변경해도 CP 300/300 일치) ② 부가 성격은 `hero['부가성격']` 원본 참조 — 효율 재계산 금지 ③ 세이브 = 필드 값 스냅샷 (성격 재해석 불요) |

// ScoreEvaluator — 09 §4-1 공식의 C# 이식
float Score(ActionDef a, Hero h, Context c) {

    return v * (1f + SeedNoise(h.Seed, a.Id) * 0.10f);           // ε ±10% 개체 시드
}

## 6. 연계 스킬 → 스토리 반응형 자동 융합 (v0.4 — 사용 기반·비고정)

> [!info] 컨셉 — "연계가 몸에 배면 하나의 기술이 된다"
> 영웅이 스킬 A를 쓰고 얼마 안 돼 스킬 B를 쓰는 것을 **반복**하면, 두 스킬 사이에 **연계스킬(A→B)**이 자라난다 — 마치 운동 선수가 두 동작을 이어서 하는 게 하나의 기술이 되는 것처럼. 연계가 익숙해지면 **자동으로 융합**되어 완전히 새로운 스킬이 태어난다. **플레이어가 누르는 게 아니라, 영웅의 습관이 기술을 만든다** — 이 게임 스킬 철학의 정점.

| 항목 | 명세 (가안 · 미정K) |
|---|---|
| 연계 판정 | 현재 구현은 스킬 A 발동 후 다음 AI 행동 B를 관찰해 연계 카운트 +1 (A→B 방향성 있음 — B→A는 별도). 시간창 5초안은 균형 플랫에서 확정한다 |
| 연계 발생 | **고정 융합표 등록 여부와 무관하게** 실제로 반복한 서로 다른 행동/스킬 쌍이 후보가 된다 — 카탈로그 쌍은 이름·어휘 힌트로만 사용 |
| 생성 게이트 | 반복 증거 3회 이상 + 현재 상황의 Hard Rule 통과 + `0.4×Rule + 0.35×Neural Policy + 0.25×JEV`가 임계 0.62 이상 |
| 스토리 조건 | 현재/최근 씬, 플래그, 계열 관계도, 야행 인장(구 혈담보), 지맥 건강도, 층을 JEV 입력으로 사용 — 스토리에 어긋난 융합은 탈락하거나 후속 생성으로 미뤄진다 |
| 연계 단계 | 현행 v0.4는 반복 증거 3회와 점수 게이트를 직접 통과하면 생성한다. 연계스킬 단계 UI·13/39/91회 임계는 후속 밸런스 확장 항목이다 |

#### 6-1. 기존 융합 쌍 카탈로그(117쌍) — 레거시 힌트, 생성 게이트 아님

> `design-docs/_tools/fusion_pairs.json`의 117쌍(FUSION-v2)은 기존 스킬 카탈로그의 이름·어휘·연계 힌트로 유지한다. v0.4 런타임은 표에 없는 부모 쌍도 생성할 수 있고, 표에 있는 쌍도 반복·Neural·JEV 조건을 통과하지 않으면 생성하지 않는다. 따라서 117쌍은 현재 데이터 마이그레이션/호환용 정본이지 행동 선택의 고정 목록이 아니다.
