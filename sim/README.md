# sim/ — 소환 규칙 게이트 (에셋 없음, 표준 라이브러리만)

## `gacha.py` 가 하는 일

`gacha.py` 는 **원본 정본의 소환 규칙을 선언하고, 시뮬레이션이 그 규칙을 실제로 재현하는지 확인하는 게이트**다.
선언한 값은 전부 원본에서 읽은 것이고, 출처는 네 곳이다 (원본 대조).

| 출처 (원본) | 무엇을 정하는가 |
|---|---|
| `design-docs/GDD_v8.0_00_확정사항.md` 확정 #32 | 확률표 ★1 70.04% · ★2 20% · ★3 8.7% · ★4 1.2% · ★5 0.05% · ★6 0.01% · 추첨 = 단일 난수 vs 누적 밴드 · ★4 소프트 피티 `SOFT_PITY_START` 70(회차당 `SOFT_PITY_STEP` 0.02)·하드 `HARD_PITY_4` 130 · ★5+ 하드 5,200(★5:★6 = 5:1 교대) · 천장 전부 비공개 (원본 대조) |
| `design-docs/GDD_v8.0_00_확정사항.md` 확정 #33 | 천장 수치 자체는 가안 — 구조만 확정 (원본 대조) |
| 확정 #11 · `design-docs/결정로그/D-276_조형생명_활성_소환률_5퍼센트.md` | 종족 롤 `SHAPED_RATE` 0.05 + `LEGACY_RATE` 0.95 (legacy `LEGACY_SPECIES` 20종 균등) · 시작 영웅 legacy-only (원본 대조) |
| 확정 #16 · #17 | `TICKET_COST` 130마석 · 최초 10회 무료 (원본 대조) |

추첨 방식도 원본을 따른다: 등급마다 재추첨하지 않고 **단일 난수를 누적 밴드에 대입**한다.
원본 기록에 따르면 등급마다 재추첨하던 구현은 ★4 이상을 33배 과소출현시켰다 (원본 대조).
그래서 `roll_rarity()` 는 난수 하나를 받아 밴드 하나를 돌려주는 순수 함수다 — 검사하기도 쉽다.

`SAMPLE_SIZE` 와 `SEED` 는 **게임 상수가 아니라 검증 파라미터**다. 그래서 `tools/tracked_numbers.json` 에 넣지 않는다.

## 돌리는 법

```bash
./.venv/bin/python sim/gacha.py
```

표본 20만 건을 고정 시드로 돌리고, 등급별 관측 분포가 정본 확률의 3시그마 안에 있는지 확인한다.
마지막 줄이 다음처럼 나오면 통과다.

```
sample=200000 seed=265
rarity: ★1=... ★2=... (등급별 관측 비율)
shaped=0.0498 (정본 0.05) legacy=0.9500
band_sum=100.00% | 최대 편차 ... | shaped 편차 ...
GATE OK: 확정 #32 확률표·#11 종족 롤 재현 (표본 200000, seed 265)
```

`tools/gate_all.py` 가 이 스크립트를 함께 돌린다. 실패하면 게이트 전체가 실패한다.

## 실패 메시지 읽는 법

| 메시지 | 뜻 |
|---|---|
| 확정 #32 확률표 합이 100%가 아닙니다 | `RARITY_BANDS` 를 고쳤는데 합이 100.00 이 아니다 — 밴드를 손대면 합부터 확인한다 |
| ★N 분포가 정본 밖입니다 | 그 등급의 관측 비율이 정본에서 3시그마를 넘었다 — 확률표나 추첨 방식이 틀렸다 |
| shaped 비율이 정본 밖입니다 | 종족 롤이 shaped 5% 계약에서 벗어났다 |

## GDScript 본체

`godot/core/gacha.gd` 가 같은 상수를 선언하고, `godot/tests/unit/test_gacha.gd` 가 그 값을 검사한다.
포팅 순서(예정): combat → summon → estate → party → tower → economy.

## 이전 판이 틀렸던 것 (기록)

| 이전 판 | 바로잡은 내용 |
|---|---|
| `PULLS = 130` — "W0 130연 게이트 재현" | 원본에 그런 게이트가 없다. W0 는 웹 껍데기 단계이고 소환 분포 게이트는 W1 이다 (원본 대조) |
| `expected_shaped = 6.5` (= 없는 횟수 × 5%) | 5% 는 종족 롤의 shaped 비율이지 소환 횟수에 곱하는 배율이 아니다 (원본 대조) |
| `D-265` 를 소환 게이트로 표기 | D-265 는 층 미션 시스템 — 주 미션 7종 + 세계 전용 특수 20종 (원본 대조) |
| 상수 이름 `LEGACY_COVERAGE` | `LEGACY_RATE` 로 바꿨다 — 값 0.95 는 그대로다 (원본 대조) |
| "원본 소스는 아직 한 줄도 읽지 못했다" | 2026-10-17에 클론해서 읽었다 (원본 대조) |

## 다음 작업 — 상수 단일 소스화

같은 상수가 `sim/gacha.py` · `godot/core/gacha.gd` · `godot/tests/unit/test_gacha.gd` 세 곳에 따로 박혀 있다.
이전 판은 "값을 대조하기 전에 통합하면 틀린 숫자를 한 곳에 예쁘게 모으는 것"이라며 통합을 미뤘고, 그 판단은 그때는 맞았다.
지금은 값이 원본 대조로 확정됐으므로 통합할 수 있다. 계획:

1. `data/` 아래에 상수 JSON 하나를 만든다 (이름은 아직 미정 — 예: game_const.json).
2. `sim/gacha.py` 와 `godot/core/gacha.gd` 가 그 JSON을 읽는다.
3. 테스트는 값을 다시 적지 않고 JSON에서 읽어 비교한다 — 그래야 JSON을 고쳤을 때 테스트가 실제로 깨진다.
4. `tools/review_docs.py` 의 CONST_DRIFT·NUMBER_CONFLICT 검사가 코드 상수와 JSON·문서 표기의 불일치를 잡는다.

아직 하지 않았다. 세 곳이 지금 같은 값인 것은 맞지만, 한 곳만 고치고 나머지를 잊으면
파이썬 게이트와 Godot 런타임이 조용히 다른 게임이 된다.
