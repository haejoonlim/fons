⚔️ FONS 테스트 센터

게임 설계가 진짜로 작동하는지 확인하는 조종석 스냅샷: 로딩 중…

👋 여기가 어디죠?

이곳은 FONS의 설계가 실제로 작동하는지 확인하는 조종석입니다. 숫자 균형(소환 확률, 경제, 마나)을 코드로 실행해 진짜 결과를 눈으로 보여줍니다. 아래 3단계를 순서대로 눌러보면 끝. 실패해도 고장 나는 게 없으니 편하게 눌러보세요.

STEP 1

🎲 주사위 돌려보기 — "소환 100연차 하면 뭐 나와?"

약 3초

가장 쉬운 첫 실험. 소환제단에서 실제 확률로 캐릭터를 뽑아봅니다. ★6이 왜 희귀한지 몸으로 느껴집니다.

💡 이걸 확인하면? "확률 1%"가 숫자가 아니라 체감임을 알게 됩니다 — 가챠 설계의 첫걸음.
STEP 2

📊 설계 상태 점검 — "지금 게임 설계, 건강한가?"

약 1분 (자동)

시뮬 스냅샷은 22종 검사를 한 번에 돌려 초록(OK)/빨강(FAIL)으로 요약해줍니다. 하나만 눌러보세요: [스냅샷 다시 찍기].

💡 이걸 확인하면? 설계가 어긋났는지(예: 50층에서 골드 부족) 1분 안에 발견할 수 있습니다.
📌 주의 — 검사 중 일부만 돌아간 스냅샷은 초록으로 "전부 통과"라고 하지 않습니다. "N종 중 M종"으로 정확히 말해줍니다.
STEP 3

⚡ 숫자를 바꿔서 놀라보기 — "천장을 10으로 바꾸면?"

약 10초

실험실에서 파라미터(천장·확률·층수)를 조절하고 [▶ 실행]만 누르면 결과가 즉시 나옵니다. 원본 설계는 절대 안 바뀌니 안심하고 만지세요.

💡 이걸 확인하면? "이 설계가 나은가?"를 감이 아니라 숫자로 비교할 수 있게 됩니다 — 밸런스 디자이너의 핵심 습관입니다.

🧭 나는 뭘 하고 싶지?

이런 상황이면…이 탭으로 가세요
게임을 처음 열어봄 / 체감용→ 🎰 소환제단 — 누르면 즉시 뽑기
"지금 설계 상태가 괜찮나?" 점검→ 📊 시뮬 스냅샷 — 전체 검사 1분
직업·키워드 배분 보기→ 🌳 직업 트리 — L1 7 · L2 26 · 키워드 94 · 티어 1/2/3 · 축 13종 · 13축 statMod
"확률·천장을 바꾸면 어때?"→ ⚡ 실험실 — 파라미터 조절 실행
생태계(마나·지맥·생물)를 보고 싶음→ 🌿 생태도감 — 도감 뷰어

❓ 이것저것 눌러도 고장 나나요?

안 나요. 이 센터는 읽기 전용 — 시뮬을 실행해도 원본 설계 파일(data/ 의 JSON 정본)은 절대 수정되지 않습니다. 무서우면 언제든 🚀 3분 데모 버튼(위쪽)을 누르세요. 순서대로 알려줍니다.

🛡 게이트 상태

런 원장을 읽는 중…

커밋 전 전체 런 돌리기

./.venv/bin/python tools/gate_all.py

→ 이 명령을 돌리면 아래 추이에 한 줄이 쌓입니다. 위쪽 [🛡 게이트 돌리기](시뮬 스냅샷 탭)는 개별 검사만 돌리므로 원장에 쌓이지 않습니다 — 추이는 커밋 전 전체 런(gate_all)의 기록입니다. 같은 내용을 터미널에서: tools/gate_all.py --history

빠른 시작

모든 명령은 저장소 루트(폰즈)에서 실행. 스냅샷 탭의 결과를 만들려면 아래 첫 명령 하나면 됩니다. 파이썬은 ./.venv/bin/python — 시스템 파이썬으로 돌려도 되지만, 그때는 터미널 로그가 아니라 이 서버를 띄운 인터프리터로 시뮬이 돌아갑니다(같은 3.9 라 결과는 같습니다).

스냅샷 (전 시뮬 1회 실행)

./.venv/bin/python sim/center/run_snapshots.py

→ 시뮬 22종 실행 → "시뮬 스냅샷" 탭에 결과 표시 · pages/snapshots.js 생성

서버 실행 (자동 리로드 + 실시간 시뮬)

./.venv/bin/python sim/center/server.py 8741

→ http://localhost:8741/ — "⚡ 실험실" 탭에서 파라미터 조절·즉시 실행 (API: /api/sims · /api/sim/<이름>). 파일 저장 시 브라우저 자동 리로드도 그대로.

통합 게이트 (커밋 전)

./.venv/bin/python tools/gate_all.py

→ tools/check_docs.py(필수 산출물 52종 · 구조 회귀 · data/ 정본 대조) + sim/gacha.py(확정 #32 확률표·#11 종족 롤) → GATE ALL OK. 매 런이 tools/gate_ledger.jsonl(gitignore)에 쌓이고, 첫 실패에서도 멈추지 않습니다.

./.venv/bin/python tools/gate_all.py --history

→ 런 원장 추이 (무엇이 계속 깨지는가 · 직전 런 대비 신규 실패)

Godot 테스트 (GUT)

./tools/test_godot.sh

→ 임포트 → GUT. junit 결과가 없거나 0건이면 실패로 끝납니다(침묵하는 거짓 통과 방지). 수 분 소요라 스냅샷에는 넣지 않았습니다.

원본 대조 (advisory)

./.venv/bin/python tools/review_docs.py

→ 문서 기계 검수 7종. 판단이 섞인 권고가 있어 게이트가 아닙니다 — exit 0 이어도 계속 봐야 합니다.

./.venv/bin/python tools/check_env.py

→ 툴체인 doctor (godot·git 필수, blender·ffmpeg·git-lfs 선택)

개별 시뮬 — 전 22종

아래 목록은 run_snapshots.py 의 SIMS 정본에서 자동 생성됩니다. 새 시뮬을 추가하면 여기에도 저절로 나타납니다. 시뮬 본체는 sim/center/sims/ 에 있고, 모두 data/ 의 정본 JSON 만 읽습니다. 원본 저장소의 GDD 문서·생성기에 기대던 2종(audit_sim·arc_parity)은 폰즈에 대조할 짝이 없어 뺐습니다 — 이유는 SIMS 주석에 적어뒀습니다.
